# Vanguard Interview — Question Bank (Grouped)

Source: notes from four prior Vanguard loops (Andy Wang 7/27 & 8/03, Vivien Zhu 5/07, Neil Prajapati 8/06) plus the prep checklist. Grouping only — no answers here. Frequency markers: **[x2]**, **[x3]** = asked in that many separate interviews. Those are the guaranteed ones.

---

## 1. Self Intro & Behavioral

- Self intro **[x3]**
- Biggest challenge (technical) **[x2]**
- A conflict story — how did you handle it
- A time you coordinated with another team **[x2]** (incl. cross-team, cross-people problem)
- A time you helped / mentored a teammate
- A time you joined a new team and had to adjust to how they work

## 2. Resume / Project Deep-Dive (expect to be challenged on details)

They dig deep and challenge what you say. Prepare a written design document for your most recent project covering:

1. Features / functionalities / system purpose / clients and why
2. Database schema (actual tables)
3. High-level design (microservice architecture) + module details
4. REST API design — be ready to design 2–4 concrete APIs
5. Data flow — 2–3 diagrams (e.g., user clicks upload → what happens across services)
6. Message queue story
7. Biggest technical challenge
8. AWS usage
9. Monitoring (log / JVM / API / APM)
10. A production support story
11. A performance tuning story
12. Most recent API you developed
13. ETL / ML pipeline + model training + inference serving story
14. GenAI / LLM / MCP / RAG story
15. Daily users / TPS / QPS numbers
16. Frontend story
17. "Where did you use multithreading in your last project?" / "Where did you use the builder pattern?" — resume-anchored pattern questions

- Did you _own_ the feature? What was your role? **[x2]**
- If you could redesign it, what would you do?

## 16. System Design Scenarios (given verbatim in prior loops)

**Scenario 1 — schema change deployed in wrong order.** Daily vendor files → batch ingest → Aurora → replicated to Redshift for ops + analytics. New column added; deploy order wrong; staging/history has mixed old/new files; production impact. Walk through: (a) investigation & root cause, (b) fast service restoration, (c) deployment strategy to prevent recurrence.

**Scenario 2 — 10–100x traffic onboarding.** GraphQL APIs on Aurora Serverless, multiple consumers. New business-critical consumer at ~5,000 sustained RPS, zero downtime tolerance, must not degrade existing consumers. Walk through: (a) evaluate current architecture & bottlenecks, (b) design for the load, (c) test before release, (d) monitoring & deployment.

## Priority read (based on frequency + checklist emphasis)

1. **GraphQL** — every interviewer touched it; N+1, supergraph, overfetch, exception handling are named.
2. **Project deep-dive with real numbers** — they cross-examine; your design doc (§2) is the backbone of the whole loop.
3. **CI/CD** — asked in 3 of 4 loops.
4. **AWS + Lambda config** — explicit.
5. **The two design scenarios** — both map almost 1:1 to your JPMC pipeline (vendor files → Glue → Aurora, GraphQL on top). Prepare them as told-stories, not improvisation.
