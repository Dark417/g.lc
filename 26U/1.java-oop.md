# Java OOP / OOD

Object-oriented design questions in Java — the "design a parking lot" round rather than the algorithm round. Section 1 is the language and design vocabulary; Section 2 is the classic questions with full implementations.

Depth target: L3 to L4. That means a clean class model with real encapsulation, interfaces at the extension points, an implementation that actually runs, and an explicit answer for "how would you extend this" and "what breaks under concurrency". It does **not** mean distributed systems — that is the system design round.

---

## Section 1: What the interviewer is grading

### 1.1 The 45-minute shape of an OOD round

1. **Clarify scope (5 min).** Ask what is in and out. "Parking lot" could mean one lot or a chain, with or without payments, with or without reservations. Write the agreed list down. Narrowing scope out loud is scored positively; silently assuming is not.
2. **Nouns become classes, verbs become methods (5 min).** Say the model out loud before writing it: `ParkingLot`, `Level`, `Spot`, `Vehicle`, `Ticket`. Call out which nouns are *values* (`Money`, `Coordinate`) and which are *entities* with identity (`Ticket`, `Vehicle`).
3. **Fix the public API (5 min).** Write the interface first: what does the caller actually invoke? `park(vehicle) -> Ticket`, `unpark(ticket) -> Fee`. Everything else is implementation detail.
4. **Implement the core flow (20 min).** One happy path end to end, compiling, with the interesting policy behind an interface.
5. **Extensions and failure modes (10 min).** Where does a new requirement land? What is the concurrency story? What did you deliberately leave out?

The classic failure is spending 30 minutes on an exhaustive class diagram and never writing a method body. Get one flow running early.

### 1.2 The four pillars, stated as things you must show in code

- **Encapsulation** — fields `private final` where possible; no public mutable collections escaping. Return `List.copyOf(...)` or an unmodifiable view, not the live list.
- **Abstraction** — the caller talks to `PricingStrategy`, not to `WeekendHourlyPricingWithHolidaySurcharge`.
- **Inheritance** — use it for genuine "is-a" specialization only. Prefer composition when you catch yourself inheriting to reuse code.
- **Polymorphism** — one call site, several behaviours. This is what makes "add a new vehicle type" a one-file change.

### 1.3 Interface vs abstract class vs enum

| Use | When |
| --- | --- |
| `interface` | A capability or contract, especially a pluggable policy. Multiple implementations, no shared state. Supports multiple inheritance of type. |
| `abstract class` | Shared *state* plus shared *code* across a real hierarchy. Single inheritance only — spend it carefully. |
| `enum` | A closed, known-at-compile-time set of values. Java enums can hold fields and override methods per constant, which makes them a lightweight strategy table. |
| `record` | An immutable value with no identity — `Money`, `Point`, `Ticket` payloads. Free `equals`/`hashCode`/`toString`. |
| `sealed interface` | A closed set of implementations you want the compiler to enforce and `switch` to exhaustively match (Java 17+). |

```java
// An enum that carries behaviour — very common in these problems
enum VehicleSize {
    MOTORCYCLE(1), COMPACT(2), LARGE(3);

    private final int requiredSpots;

    VehicleSize(int requiredSpots) { this.requiredSpots = requiredSpots; }

    public int requiredSpots() { return requiredSpots; }
}
```

### 1.4 SOLID, phrased as what it changes in your answer

- **S**ingle responsibility — `ParkingLot` assigns spots; it does not also compute fees and print receipts. If a class name needs "and", split it.
- **O**pen/closed — adding an `ELECTRIC` vehicle type should not edit `ParkingLot`. That is what a strategy interface or a per-constant enum buys you.
- **L**iskov substitution — any `Vehicle` subtype must work everywhere `Vehicle` works. A `Bicycle` that throws from `park()` violates this; it means your hierarchy is wrong.
- **I**nterface segregation — small interfaces. `PricingStrategy` and `SpotAssignmentStrategy` beat one `ParkingPolicy` with six methods where implementations no-op half of them.
- **D**ependency inversion — `ParkingLot` takes a `PricingStrategy` in its constructor. It never calls `new HourlyPricing()` itself. This is also what makes it testable.

### 1.5 The seven patterns that cover almost every OOD question

| Pattern | Recognize it by | Shows up in |
| --- | --- | --- |
| **Strategy** | "The rule for X should be swappable" | Pricing, spot assignment, eviction, matching |
| **State** | "The object behaves differently depending on its current mode" | Vending machine, elevator, order lifecycle |
| **Factory** | "Create the right subtype from input data" | `Vehicle.of(type)`, parser dispatch |
| **Observer** | "Notify interested parties when something happens" | Display boards, event bus, pub/sub |
| **Command** | "Actions need to be queued, logged, or undone" | Text editor undo/redo, transaction log |
| **Singleton** | "Exactly one instance" | Rarely the right answer; prefer dependency injection. If asked, use an `enum` singleton. |
| **Builder** | "This constructor has eight parameters" | Config objects, immutable entities with optional fields |

State vs Strategy is a common interviewer probe: **Strategy** is chosen by the *caller* and does not change itself; **State** is owned by the *object* and each state decides the next one.

### 1.6 Concurrency answers that land

You will not be asked to write a lock-free algorithm, but you will be asked "what if two cars arrive at once".

- Name the shared mutable state explicitly (the free-spot pool, the ticket map).
- Reach for `java.util.concurrent` before `synchronized`: `ConcurrentHashMap`, `AtomicInteger`, `BlockingQueue`, `ReentrantLock`.
- `ConcurrentHashMap` makes individual operations atomic but **not** compound ones. `if (!map.containsKey(k)) map.put(k, v)` is still a race — use `putIfAbsent` / `computeIfAbsent`.
- Say where the lock lives and how coarse it is. "One lock per level rather than one for the whole lot, so two levels can admit cars concurrently" is a good L4 answer.
- Prefer immutable value objects (`record`) — they need no synchronization at all.

### 1.7 Java details these questions actually exercise

```java
// equals/hashCode contract — mandatory for anything used as a Map key or Set element
@Override public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof Ticket other)) return false;      // pattern matching, Java 16+
    return id.equals(other.id);
}
@Override public int hashCode() { return Objects.hash(id); }

// Defensive copies — do not hand out your internals
public List<Spot> getSpots() { return List.copyOf(spots); }

// Money: never use double for currency; use long cents or BigDecimal
record Money(long cents) {
    Money plus(Money o) { return new Money(cents + o.cents); }
}

// Comparable for natural ordering, Comparator for everything else
record Request(int priority) implements Comparable<Request> {
    public int compareTo(Request o) { return Integer.compare(priority, o.priority); }
}
```

### 1. Design a Parking Lot

**Problem.** Model a multi-level parking lot. Vehicles of different sizes arrive, get assigned a spot, receive a ticket, and pay on exit based on duration.

**Clarify first.** Single lot or a chain? Are motorcycles allowed in car spots? Do we need reservations? Is pricing flat, hourly, or tiered? Do we track spot *availability counts* only, or exact spot identity? — Assume: one lot, multiple levels, exact spot identity, smaller vehicles may use larger spots, hourly pricing, no reservations.

**Model.**

- `Vehicle` is an abstract entity with a `VehicleSize`. Subclasses add nothing behavioural yet — that is fine and worth saying out loud; the size enum carries the variation.
- `Spot` knows its size and its occupant. It does **not** know about pricing.
- `Level` owns its spots and is the natural unit of locking.
- `ParkingLot` is the façade: `park` and `unpark`.
- `SpotAssignmentStrategy` and `PricingStrategy` are injected, so "charge double on weekends" or "pack cars nearest the entrance" never touches `ParkingLot`.

**Key decision.** Keeping the free spots in a `Deque` **per size** turns assignment into O(1) instead of scanning every spot. The "smaller vehicle can use a bigger spot" rule then becomes: walk sizes upward until a pool is non-empty.

```java
import java.time.Duration;
import java.time.Instant;
import java.util.*;
import java.util.concurrent.ConcurrentHashMap;

enum VehicleSize {
    MOTORCYCLE, COMPACT, LARGE;

    /** Spot sizes that can hold this vehicle, smallest first. */
    List<VehicleSize> fittingSpots() {
        return switch (this) {
            case MOTORCYCLE -> List.of(MOTORCYCLE, COMPACT, LARGE);
            case COMPACT    -> List.of(COMPACT, LARGE);
            case LARGE      -> List.of(LARGE);
        };
    }
}

abstract class Vehicle {
    private final String licensePlate;
    private final VehicleSize size;

    protected Vehicle(String licensePlate, VehicleSize size) {
        this.licensePlate = Objects.requireNonNull(licensePlate);
        this.size = Objects.requireNonNull(size);
    }

    public String licensePlate() { return licensePlate; }
    public VehicleSize size() { return size; }
}

class Motorcycle extends Vehicle {
    public Motorcycle(String plate) { super(plate, VehicleSize.MOTORCYCLE); }
}

class Car extends Vehicle {
    public Car(String plate) { super(plate, VehicleSize.COMPACT); }
}

class Truck extends Vehicle {
    public Truck(String plate) { super(plate, VehicleSize.LARGE); }
}

final class Spot {
    private final String id;
    private final int levelNumber;
    private final VehicleSize size;
    private Vehicle occupant;

    Spot(String id, int levelNumber, VehicleSize size) {
        this.id = id;
        this.levelNumber = levelNumber;
        this.size = size;
    }

    String id() { return id; }
    int levelNumber() { return levelNumber; }
    VehicleSize size() { return size; }
    boolean isFree() { return occupant == null; }

    void occupy(Vehicle v) {
        if (occupant != null) throw new IllegalStateException("spot " + id + " is taken");
        occupant = v;
    }

    void release() { occupant = null; }
}

record Ticket(String id, String spotId, String licensePlate, Instant issuedAt) {}

/** Pluggable pricing. Adding weekend rates never touches ParkingLot. */
interface PricingStrategy {
    long feeInCents(Ticket ticket, Instant exitTime);
}

class HourlyPricing implements PricingStrategy {
    private final long centsPerHour;

    HourlyPricing(long centsPerHour) { this.centsPerHour = centsPerHour; }

    @Override
    public long feeInCents(Ticket ticket, Instant exitTime) {
        long minutes = Duration.between(ticket.issuedAt(), exitTime).toMinutes();
        long hours = Math.max(1, (minutes + 59) / 60);      // round up, minimum one hour
        return hours * centsPerHour;
    }
}

/** Pluggable placement. Nearest-to-entrance vs. spread-across-levels lives here. */
interface SpotAssignmentStrategy {
    Optional<Spot> assign(List<Level> levels, Vehicle vehicle);
}

class FirstAvailableAssignment implements SpotAssignmentStrategy {
    @Override
    public Optional<Spot> assign(List<Level> levels, Vehicle vehicle) {
        for (Level level : levels) {
            Optional<Spot> spot = level.takeFreeSpot(vehicle.size());
            if (spot.isPresent()) return spot;
        }
        return Optional.empty();
    }
}

final class Level {
    private final int number;
    private final Map<VehicleSize, Deque<Spot>> freeBySize = new EnumMap<>(VehicleSize.class);
    private final Object lock = new Object();               // one lock per level, not per lot

    Level(int number, Map<VehicleSize, Integer> spotCounts) {
        this.number = number;
        for (VehicleSize size : VehicleSize.values()) freeBySize.put(size, new ArrayDeque<>());

        int seq = 0;
        for (Map.Entry<VehicleSize, Integer> e : spotCounts.entrySet()) {
            for (int i = 0; i < e.getValue(); i++) {
                freeBySize.get(e.getKey())
                          .push(new Spot("L" + number + "-S" + (seq++), number, e.getKey()));
            }
        }
    }

    int number() { return number; }

    /** Take the smallest spot that fits, or empty. O(1). */
    Optional<Spot> takeFreeSpot(VehicleSize vehicleSize) {
        synchronized (lock) {
            for (VehicleSize candidate : vehicleSize.fittingSpots()) {
                Deque<Spot> pool = freeBySize.get(candidate);
                if (!pool.isEmpty()) return Optional.of(pool.pop());
            }
            return Optional.empty();
        }
    }

    void returnSpot(Spot spot) {
        synchronized (lock) {
            spot.release();
            freeBySize.get(spot.size()).push(spot);
        }
    }

    int freeCount() {
        synchronized (lock) {
            return freeBySize.values().stream().mapToInt(Deque::size).sum();
        }
    }
}

class ParkingLot {
    private final List<Level> levels;
    private final SpotAssignmentStrategy assignment;
    private final PricingStrategy pricing;
    private final Map<String, Spot> occupiedByTicket = new ConcurrentHashMap<>();
    private final Map<String, Level> levelByTicket = new ConcurrentHashMap<>();

    public ParkingLot(List<Level> levels, SpotAssignmentStrategy assignment, PricingStrategy pricing) {
        this.levels = List.copyOf(levels);
        this.assignment = assignment;
        this.pricing = pricing;
    }

    /** @throws IllegalStateException when the lot is full. */
    public Ticket park(Vehicle vehicle) {
        Spot spot = assignment.assign(levels, vehicle)
            .orElseThrow(() -> new IllegalStateException("lot full for " + vehicle.size()));
        spot.occupy(vehicle);

        Ticket ticket = new Ticket(UUID.randomUUID().toString(), spot.id(),
                                   vehicle.licensePlate(), Instant.now());
        occupiedByTicket.put(ticket.id(), spot);
        levelByTicket.put(ticket.id(), levels.get(spot.levelNumber()));
        return ticket;
    }

    /** @return the fee in cents. */
    public long unpark(Ticket ticket, Instant exitTime) {
        Spot spot = occupiedByTicket.remove(ticket.id());
        if (spot == null) throw new IllegalArgumentException("unknown or already-used ticket");
        levelByTicket.remove(ticket.id()).returnSpot(spot);
        return pricing.feeInCents(ticket, exitTime);
    }

    public int availableSpots() {
        return levels.stream().mapToInt(Level::freeCount).sum();
    }
}
```

**Extensions, and where each one lands.**

- *Electric vehicles needing chargers* → a new `VehicleSize` value plus a `hasCharger` flag on `Spot`, and a `ChargingAwareAssignment implements SpotAssignmentStrategy`. `ParkingLot` is untouched.
- *Weekend/holiday rates* → a new `PricingStrategy`. Untouched again. This is the payoff for injecting both policies.
- *Reservations* → a `Reservation` entity and a spot state of `FREE / RESERVED / OCCUPIED`. This one genuinely does change `Spot`, which is the honest answer.
- *Multiple lots* → `ParkingLot` becomes an entity with an id; a `LotDirectory` sits above it. Do not pre-build this unless asked.
- *A vehicle spanning multiple spots (a bus over 5 compacts)* → assignment must become "find k contiguous spots", which breaks the O(1) `Deque`. Say so; it is a real cost, and volunteering it scores better than pretending the design absorbs everything.

**Concurrency.** The free-spot pools are the shared mutable state, and the lock is per `Level`, so two levels admit cars in parallel. `occupiedByTicket` is a `ConcurrentHashMap` and `remove` returning the spot is what makes double-unpark safe — the second call gets `null` rather than double-releasing. The `Spot.occupy` call sits outside the level lock, which is safe only because the spot has already been removed from the pool and is therefore owned exclusively by this thread.

### 2. Design a Vending Machine

**Problem.** A machine holds products in slots. A user inserts coins, selects a product, and receives the product plus change — or a refund if they cancel.

**Clarify first.** Which denominations? Do we make change, and what if we cannot? Can the user select before paying? Is refund allowed mid-transaction? — Assume: fixed coin set, change required (fail the sale if we cannot make it), pay-then-select, cancel allowed before dispensing.

**Model.** This is the textbook **State** pattern: the machine's response to `insertCoin` depends entirely on which state it is in. Encoding that as a `switch` over an enum field works but grows quadratically; giving each state its own class keeps every transition in one readable place.

**Key decision.** Making change is a coin-change problem. With canonical denominations greedy is optimal, so greedy is the right call here — but say the words "this is only correct because the denominations are canonical", because that is exactly what the interviewer is listening for.

```java
import java.util.*;

enum Coin {
    NICKEL(5), DIME(10), QUARTER(25), DOLLAR(100);

    private final int cents;

    Coin(int cents) { this.cents = cents; }

    public int cents() { return cents; }
}

record Product(String code, String name, int priceCents) {}

/** Each state decides what the machine does next. */
interface MachineState {
    default void insertCoin(VendingMachine m, Coin c) { throw new IllegalStateException("cannot insert now"); }
    default void select(VendingMachine m, String code)  { throw new IllegalStateException("cannot select now"); }
    default void dispense(VendingMachine m)             { throw new IllegalStateException("nothing to dispense"); }
    default List<Coin> cancel(VendingMachine m)         { throw new IllegalStateException("nothing to cancel"); }
    String name();
}

class IdleState implements MachineState {
    public String name() { return "IDLE"; }

    @Override public void insertCoin(VendingMachine m, Coin c) {
        m.addToBalance(c);
        m.setState(new HasMoneyState());
    }
}

class HasMoneyState implements MachineState {
    public String name() { return "HAS_MONEY"; }

    @Override public void insertCoin(VendingMachine m, Coin c) { m.addToBalance(c); }

    @Override public void select(VendingMachine m, String code) {
        Product p = m.productFor(code);
        if (p == null) throw new IllegalArgumentException("no such product: " + code);
        if (m.stockOf(code) == 0) throw new IllegalStateException("sold out: " + code);
        if (m.balanceCents() < p.priceCents()) {
            throw new IllegalStateException("insufficient funds, need " + p.priceCents());
        }
        // Verify change is possible BEFORE committing the sale.
        int changeDue = m.balanceCents() - p.priceCents();
        if (m.planChange(changeDue) == null) {
            throw new IllegalStateException("cannot make exact change");
        }
        m.setSelection(p);
        m.setState(new DispensingState());
    }

    @Override public List<Coin> cancel(VendingMachine m) {
        List<Coin> refund = m.drainInserted();
        m.setState(new IdleState());
        return refund;
    }
}

class DispensingState implements MachineState {
    public String name() { return "DISPENSING"; }

    @Override public void dispense(VendingMachine m) {
        m.completeSale();
        m.setState(new IdleState());
    }

    @Override public List<Coin> cancel(VendingMachine m) {
        List<Coin> refund = m.drainInserted();
        m.clearSelection();
        m.setState(new IdleState());
        return refund;
    }
}

class VendingMachine {
    private MachineState state = new IdleState();
    private final Map<String, Product> catalog = new LinkedHashMap<>();
    private final Map<String, Integer> stock = new HashMap<>();
    private final Map<Coin, Integer> bank = new EnumMap<>(Coin.class);
    private final List<Coin> inserted = new ArrayList<>();
    private Product selection;
    private final List<Product> outputTray = new ArrayList<>();
    private List<Coin> changeTray = List.of();

    public VendingMachine() {
        for (Coin c : Coin.values()) bank.put(c, 0);
    }

    // ---- setup ----
    public void load(Product p, int quantity) {
        catalog.put(p.code(), p);
        stock.merge(p.code(), quantity, Integer::sum);
    }

    public void loadCoins(Coin c, int count) { bank.merge(c, count, Integer::sum); }

    // ---- public API: delegate everything to the current state ----
    public void insertCoin(Coin c)      { state.insertCoin(this, c); }
    public void select(String code)     { state.select(this, code); }
    public void dispense()              { state.dispense(this); }
    public List<Coin> cancel()          { return state.cancel(this); }
    public String stateName()           { return state.name(); }

    public List<Product> collectProducts() {
        List<Product> out = List.copyOf(outputTray);
        outputTray.clear();
        return out;
    }

    public List<Coin> collectChange() {
        List<Coin> out = changeTray;
        changeTray = List.of();
        return out;
    }

    // ---- package-internal helpers used by the states ----
    void setState(MachineState s)     { this.state = s; }
    void addToBalance(Coin c)         { inserted.add(c); }
    void setSelection(Product p)      { this.selection = p; }
    void clearSelection()             { this.selection = null; }
    Product productFor(String code)   { return catalog.get(code); }
    int stockOf(String code)          { return stock.getOrDefault(code, 0); }

    int balanceCents() {
        return inserted.stream().mapToInt(Coin::cents).sum();
    }

    List<Coin> drainInserted() {
        List<Coin> refund = List.copyOf(inserted);
        inserted.clear();
        return refund;
    }

    /**
     * Greedy change planning. Correct here only because these denominations are
     * canonical (5/10/25/100); an arbitrary coin set would need DP.
     * @return the coins to return, or null if exact change is impossible.
     */
    List<Coin> planChange(int amountCents) {
        if (amountCents == 0) return List.of();

        List<Coin> plan = new ArrayList<>();
        Coin[] descending = {Coin.DOLLAR, Coin.QUARTER, Coin.DIME, Coin.NICKEL};

        for (Coin c : descending) {
            int available = bank.get(c);
            while (amountCents >= c.cents() && available > 0) {
                plan.add(c);
                amountCents -= c.cents();
                available--;
            }
        }
        return amountCents == 0 ? plan : null;
    }

    /** Commit: bank the coins, hand over product and change. */
    void completeSale() {
        int changeDue = balanceCents() - selection.priceCents();
        List<Coin> change = planChange(changeDue);
        if (change == null) throw new IllegalStateException("change became unavailable");

        for (Coin c : inserted) bank.merge(c, 1, Integer::sum);
        inserted.clear();
        for (Coin c : change) bank.merge(c, -1, Integer::sum);

        stock.merge(selection.code(), -1, Integer::sum);
        outputTray.add(selection);
        changeTray = change;
        selection = null;
    }
}
```

**Extensions.**

- *Card payments* → a `PaymentMethod` interface with `Coins` and `Card` implementations. The state machine keeps its shape; only "collect payment" changes.
- *Arbitrary denominations* → replace greedy `planChange` with a coin-change DP over the bank inventory (bounded knapsack, since coin counts are finite). Worth naming even if you do not write it.
- *Maintenance mode* → one more state class. That is the whole point of the pattern: new behaviour, no edits to existing states.

**Concurrency.** A physical machine has one user, so a single lock on the machine is correct and honest. Do not over-engineer this one; the interesting concurrency answer here is that `planChange` is checked at selection but the bank could change before `completeSale`, which is why the commit re-checks and throws rather than dispensing with wrong change.

**Common trap.** Verifying change *after* taking the money. Check feasibility during `select`, commit during `dispense`.

### 3. Design an Elevator System

**Problem.** A building with `n` floors and `m` elevator cars. People press an up/down button on a floor (a *hall call*) or a floor button inside a car (a *car call*). Move cars to serve everyone.

**Clarify first.** How many cars? Is it express/local, or do all cars serve all floors? Optimize for average wait or worst-case wait? Do we need to model door timing and capacity? — Assume: `m` identical cars serving all floors, simulation advances in discrete ticks, optimize average wait, capacity ignored.

**Model.** Two distinct request types is the insight most candidates miss: a **car call** belongs to one specific elevator, while a **hall call** must be *dispatched* to one of them. That dispatch rule is the whole interesting part, so it goes behind an interface.

**Key decision.** Each car keeps two sorted sets of target floors: those ahead in its current direction, and those it will pick up on the return trip. This is the classic elevator (SCAN) algorithm and it is why a car passing floor 5 going up will serve a floor-7 request but defer a floor-3 one.

```java
import java.util.*;

enum Direction { UP, DOWN, IDLE }

record HallCall(int floor, Direction direction) {}

class Elevator {
    private final int id;
    private final int minFloor, maxFloor;
    private int currentFloor;
    private Direction direction = Direction.IDLE;

    // Floors to stop at, split by travel direction. TreeSet keeps them ordered.
    private final NavigableSet<Integer> upStops = new TreeSet<>();
    private final NavigableSet<Integer> downStops = new TreeSet<>();

    Elevator(int id, int minFloor, int maxFloor) {
        this.id = id;
        this.minFloor = minFloor;
        this.maxFloor = maxFloor;
        this.currentFloor = minFloor;
    }

    int id() { return id; }
    int currentFloor() { return currentFloor; }
    Direction direction() { return direction; }
    boolean isIdle() { return direction == Direction.IDLE && upStops.isEmpty() && downStops.isEmpty(); }

    int pendingStops() { return upStops.size() + downStops.size(); }

    void requestStop(int floor) {
        if (floor < minFloor || floor > maxFloor) {
            throw new IllegalArgumentException("floor out of range: " + floor);
        }
        if (floor == currentFloor) return;
        if (floor > currentFloor) upStops.add(floor);
        else downStops.add(floor);
        if (direction == Direction.IDLE) {
            direction = floor > currentFloor ? Direction.UP : Direction.DOWN;
        }
    }

    /** Advance one floor. @return true if the car stops here (doors open). */
    boolean step() {
        if (isIdle()) return false;

        if (direction == Direction.UP) {
            Integer next = upStops.ceiling(currentFloor + 1);
            if (next == null) {                     // nothing left above: reverse
                direction = downStops.isEmpty() ? Direction.IDLE : Direction.DOWN;
                return false;
            }
            currentFloor++;
            if (upStops.remove(currentFloor)) {
                if (upStops.isEmpty()) direction = downStops.isEmpty() ? Direction.IDLE : Direction.DOWN;
                return true;
            }
        } else {
            Integer next = downStops.floor(currentFloor - 1);
            if (next == null) {
                direction = upStops.isEmpty() ? Direction.IDLE : Direction.UP;
                return false;
            }
            currentFloor--;
            if (downStops.remove(currentFloor)) {
                if (downStops.isEmpty()) direction = upStops.isEmpty() ? Direction.IDLE : Direction.UP;
                return true;
            }
        }
        return false;
    }
}

/** How a hall call is routed to a car. The interesting, swappable part. */
interface DispatchStrategy {
    Optional<Elevator> pick(List<Elevator> cars, HallCall call);
}

/**
 * Prefer a car already heading toward the caller in the right direction;
 * fall back to the nearest idle car; last resort, the least-loaded car.
 */
class NearestSuitableDispatch implements DispatchStrategy {
    @Override
    public Optional<Elevator> pick(List<Elevator> cars, HallCall call) {
        Elevator best = null;
        int bestScore = Integer.MAX_VALUE;

        for (Elevator e : cars) {
            int distance = Math.abs(e.currentFloor() - call.floor());
            int score;

            if (e.isIdle()) {
                score = distance * 2;                                  // available, but must travel
            } else if (e.direction() == call.direction() && movingToward(e, call)) {
                score = distance;                                      // already on the way
            } else {
                score = distance * 3 + e.pendingStops() * 2;           // will need a full reversal
            }

            if (score < bestScore) {
                bestScore = score;
                best = e;
            }
        }
        return Optional.ofNullable(best);
    }

    private boolean movingToward(Elevator e, HallCall call) {
        return call.direction() == Direction.UP
            ? e.currentFloor() <= call.floor()
            : e.currentFloor() >= call.floor();
    }
}

class ElevatorSystem {
    private final List<Elevator> cars;
    private final DispatchStrategy dispatch;
    private final Deque<HallCall> unassigned = new ArrayDeque<>();

    public ElevatorSystem(int carCount, int minFloor, int maxFloor, DispatchStrategy dispatch) {
        List<Elevator> list = new ArrayList<>();
        for (int i = 0; i < carCount; i++) list.add(new Elevator(i, minFloor, maxFloor));
        this.cars = List.copyOf(list);
        this.dispatch = dispatch;
    }

    /** Someone pressed up/down in a lobby. */
    public void requestHallCall(int floor, Direction direction) {
        HallCall call = new HallCall(floor, direction);
        Optional<Elevator> car = dispatch.pick(cars, call);
        if (car.isPresent()) car.get().requestStop(floor);
        else unassigned.offer(call);                       // retried next tick
    }

    /** Someone inside car {@code carId} pressed a floor button. */
    public void requestCarCall(int carId, int floor) {
        cars.get(carId).requestStop(floor);
    }

    /** Advance the whole system one tick. @return car ids that opened doors. */
    public List<Integer> tick() {
        int retries = unassigned.size();
        for (int i = 0; i < retries; i++) {
            HallCall call = unassigned.poll();
            dispatch.pick(cars, call).ifPresentOrElse(
                e -> e.requestStop(call.floor()),
                () -> unassigned.offer(call));
        }

        List<Integer> stopped = new ArrayList<>();
        for (Elevator e : cars) {
            if (e.step()) stopped.add(e.id());
        }
        return stopped;
    }

    public List<Elevator> cars() { return cars; }
}
```

**Extensions.**

- *Express elevators (skip floors 2–10)* → give `Elevator` a `servesFloor(int)` predicate and have the dispatcher filter on it. No change to the SCAN logic.
- *Capacity limits* → `Elevator` tracks occupancy; a full car stops accepting hall calls but still honours its car calls. Hall calls it cannot take go back to `unassigned`.
- *Optimizing worst-case rather than average wait* → swap the `DispatchStrategy` to one that scores by the *oldest* waiting call rather than distance. This is the reason dispatch is an interface.
- *Fire/emergency mode* → a system-level mode flag that clears all stops and sends every car to the ground floor. Model as a state on `ElevatorSystem`, not on each car.

**Concurrency.** Button presses arrive from many threads; the tick loop is a single simulation thread. The clean split is a `BlockingQueue` of requests drained at the start of each tick, so each `Elevator`'s stop sets are only ever touched by the tick thread and need no locking at all. Say this explicitly — "make the mutable state single-threaded and queue the inputs" is a stronger answer than sprinkling `synchronized`.

### 4. Design a Deck of Cards / Blackjack

**Problem.** Model a standard 52-card deck, deal from it, and build enough of Blackjack to show the model works.

**Clarify first.** One deck or a multi-deck shoe? Are jokers included? Does the hand-value logic need to handle soft aces? — Assume: configurable number of decks, no jokers, aces count 11 unless that busts, then 1.

**Model.** `Suit` and `Rank` are enums, and `Card` is a `record` — an immutable value with no identity, which is exactly what `record` is for. `Deck` owns the shuffle. `Hand` owns scoring, because the ace rule is the only real logic in the problem and it does not belong in `Player`.

**Key decision.** Use `Collections.shuffle(list, random)`, and be ready to explain that it is Fisher-Yates: uniform over all `n!` permutations. Interviewers do ask "is your shuffle fair?", and "I sort by a random key" or "I swap random pairs n times" are both wrong answers.

**Soft-ace rule.** Count every ace as 1, then upgrade *one* ace to 11 if that still fits under 21. Looping to "downgrade aces while busting" also works, but the upgrade form is a single conditional.

```java
import java.util.*;

enum Suit { CLUBS, DIAMONDS, HEARTS, SPADES }

enum Rank {
    TWO(2), THREE(3), FOUR(4), FIVE(5), SIX(6), SEVEN(7), EIGHT(8),
    NINE(9), TEN(10), JACK(10), QUEEN(10), KING(10), ACE(1);

    private final int blackjackValue;

    Rank(int blackjackValue) { this.blackjackValue = blackjackValue; }

    public int blackjackValue() { return blackjackValue; }
}

record Card(Rank rank, Suit suit) {
    @Override public String toString() { return rank + " of " + suit; }
}

class Deck {
    private final Deque<Card> cards = new ArrayDeque<>();
    private final Random random;

    public Deck(int deckCount, Random random) {
        this.random = random;
        List<Card> all = new ArrayList<>();
        for (int d = 0; d < deckCount; d++) {
            for (Suit s : Suit.values()) {
                for (Rank r : Rank.values()) all.add(new Card(r, s));
            }
        }
        Collections.shuffle(all, random);                  // Fisher-Yates: uniform over n!
        cards.addAll(all);
    }

    public int remaining() { return cards.size(); }

    /** @throws IllegalStateException when the shoe is empty. */
    public Card draw() {
        if (cards.isEmpty()) throw new IllegalStateException("deck exhausted");
        return cards.pop();
    }

    public void reshuffle(Collection<Card> discards) {
        List<Card> all = new ArrayList<>(cards);
        all.addAll(discards);
        Collections.shuffle(all, random);
        cards.clear();
        cards.addAll(all);
    }
}

class Hand {
    private final List<Card> cards = new ArrayList<>();

    public void add(Card c) { cards.add(c); }

    public List<Card> cards() { return List.copyOf(cards); }

    public int size() { return cards.size(); }

    /** Best score at or under 21 if one exists, otherwise the hard total. */
    public int score() {
        int total = 0;
        boolean hasAce = false;
        for (Card c : cards) {
            total += c.rank().blackjackValue();
            if (c.rank() == Rank.ACE) hasAce = true;
        }
        if (hasAce && total + 10 <= 21) total += 10;       // upgrade exactly one ace to 11
        return total;
    }

    public boolean isSoft() {
        int hard = cards.stream().mapToInt(c -> c.rank().blackjackValue()).sum();
        return cards.stream().anyMatch(c -> c.rank() == Rank.ACE) && hard + 10 <= 21;
    }

    public boolean isBusted() { return score() > 21; }

    public boolean isBlackjack() { return cards.size() == 2 && score() == 21; }
}

/** How a seat decides to hit or stand. Lets the dealer and a player share one loop. */
interface PlayStrategy {
    boolean shouldHit(Hand hand);
}

/** Dealer rule: hit until 17, standing on soft 17. */
class DealerStrategy implements PlayStrategy {
    @Override public boolean shouldHit(Hand hand) { return hand.score() < 17; }
}

class ThresholdStrategy implements PlayStrategy {
    private final int standAt;

    ThresholdStrategy(int standAt) { this.standAt = standAt; }

    @Override public boolean shouldHit(Hand hand) { return hand.score() < standAt; }
}

class BlackjackGame {
    public enum Outcome { PLAYER_WIN, DEALER_WIN, PUSH }

    private final Deck deck;

    public BlackjackGame(Deck deck) { this.deck = deck; }

    public Outcome playRound(PlayStrategy player) {
        Hand playerHand = new Hand();
        Hand dealerHand = new Hand();
        PlayStrategy dealer = new DealerStrategy();

        playerHand.add(deck.draw());
        dealerHand.add(deck.draw());
        playerHand.add(deck.draw());
        dealerHand.add(deck.draw());

        if (playerHand.isBlackjack() || dealerHand.isBlackjack()) {
            return settle(playerHand, dealerHand);
        }

        while (player.shouldHit(playerHand)) {
            playerHand.add(deck.draw());
            if (playerHand.isBusted()) return Outcome.DEALER_WIN;
        }
        while (dealer.shouldHit(dealerHand)) {
            dealerHand.add(deck.draw());
            if (dealerHand.isBusted()) return Outcome.PLAYER_WIN;
        }
        return settle(playerHand, dealerHand);
    }

    private Outcome settle(Hand player, Hand dealer) {
        int p = player.score(), d = dealer.score();
        if (p > d) return Outcome.PLAYER_WIN;
        if (p < d) return Outcome.DEALER_WIN;
        return Outcome.PUSH;
    }
}
```

**Extensions.**

- *A different card game* → `Rank.blackjackValue` is a leak: it hardcodes one game's rules into a shared enum. The clean fix is a `ScoringRules` interface mapping `Rank -> int`, with the enum staying game-agnostic. Naming this leak yourself is the L4 move.
- *Splits and doubling down* → `playRound` returns a list of `Hand`s per seat, and `PlayStrategy` returns an `Action` enum (`HIT / STAND / SPLIT / DOUBLE`) instead of a boolean.
- *Card counting / shoe penetration* → `Deck` exposes `remaining()`, and a strategy can observe dealt cards through an `Observer`.

**Concurrency.** Not naturally concurrent — one dealer, sequential turns. The honest answer is "a table is single-threaded; a *server* running many tables gives each table its own thread and shares nothing but the RNG, which must then be per-table since `Random` under contention is both a correctness and a performance problem".

### 5. Design Tic-Tac-Toe

**Problem.** An `n x n` board, two players alternating. Report a win as soon as it happens.

**Clarify first.** Fixed 3x3 or general `n`? Do we need move validation and undo? Is the API "call `move` and get the winner back" (LC 348) or a full game object? — Assume: general `n`, `move(row, col, player)` returns the winner or 0, moves validated.

**Key decision — and the whole point of this question.** The naive win check scans the row, column, and both diagonals: O(n) per move. The interviewer will ask for O(1). Keep running counters instead: `+1` for player 1, `-1` for player 2, per row, per column, and for each diagonal. A counter hitting `±n` means that line is complete. This is the entire trick, and it generalizes to Connect-N with a per-direction run length.

```java
import java.util.*;

class TicTacToe {
    private final int n;
    private final int[] rows;
    private final int[] cols;
    private int diagonal;
    private int antiDiagonal;
    private final int[][] board;      // 0 = empty, 1 = player 1, 2 = player 2
    private int movesPlayed;
    private int winner;               // 0 = none yet

    private final Deque<int[]> history = new ArrayDeque<>();   // {row, col, player}

    public TicTacToe(int n) {
        this.n = n;
        this.rows = new int[n];
        this.cols = new int[n];
        this.board = new int[n][n];
    }

    /**
     * Place a mark.
     * @return the winning player (1 or 2), or 0 if there is no winner yet.
     * @throws IllegalStateException if the game is over or the cell is taken.
     */
    public int move(int row, int col, int player) {
        if (winner != 0) throw new IllegalStateException("game already won by " + winner);
        if (row < 0 || row >= n || col < 0 || col >= n) {
            throw new IllegalArgumentException("off board");
        }
        if (board[row][col] != 0) throw new IllegalStateException("cell already taken");
        if (player != 1 && player != 2) throw new IllegalArgumentException("player must be 1 or 2");

        int delta = player == 1 ? 1 : -1;
        board[row][col] = player;
        history.push(new int[]{row, col, player});
        movesPlayed++;

        rows[row] += delta;
        cols[col] += delta;
        if (row == col) diagonal += delta;
        if (row + col == n - 1) antiDiagonal += delta;

        if (Math.abs(rows[row]) == n || Math.abs(cols[col]) == n
            || Math.abs(diagonal) == n || Math.abs(antiDiagonal) == n) {
            winner = player;
        }
        return winner;
    }

    /** Undo comes free: every counter update is its own inverse. */
    public void undo() {
        if (history.isEmpty()) throw new IllegalStateException("no moves to undo");

        int[] last = history.pop();
        int row = last[0], col = last[1], player = last[2];
        int delta = player == 1 ? 1 : -1;

        board[row][col] = 0;
        movesPlayed--;
        rows[row] -= delta;
        cols[col] -= delta;
        if (row == col) diagonal -= delta;
        if (row + col == n - 1) antiDiagonal -= delta;
        winner = 0;
    }

    public boolean isDraw() { return winner == 0 && movesPlayed == n * n; }

    public int winner() { return winner; }

    public int[][] snapshot() {
        int[][] copy = new int[n][];
        for (int i = 0; i < n; i++) copy[i] = board[i].clone();
        return copy;                                        // defensive copy
    }
}
```

**Extensions.**

- *More than two players* → the `±1` trick breaks, because two different players' marks would cancel. Switch to `count[line][player]` and check `count[line][p] == n`. Volunteer this; it is the natural follow-up.
- *Connect-N on an `m x n` board* → counters no longer work, since a win is any run of `k`, not a full line. Check only the four directions through the just-played cell and count the run in each — still O(k), not O(mn).
- *Undo* → shown above. It is free precisely because every counter update is an increment, and increments invert exactly.
- *An AI opponent* → minimax with alpha-beta pruning behind a `MoveStrategy` interface, so `HumanPlayer` and `AiPlayer` are interchangeable.

**Concurrency.** A turn-based game is inherently serialized. If moves arrive over a network, the real requirement is *turn enforcement*, not locking: reject a move whose player is not the current player. Say that — the interviewer is checking whether you reach for a lock reflexively when the domain already gives you mutual exclusion.

### 6. Design a Text Editor with Undo/Redo

**Problem.** A text buffer supporting insert, delete, and replace, with unlimited undo and redo.

**Clarify first.** Character-level or line-level? Must undo be unlimited or bounded? Should consecutive typed characters coalesce into one undo step? — Assume: character offsets, bounded history, no coalescing (mention it as an extension).

**Key decision.** Two viable designs, and choosing correctly is the point of the question:

| | Snapshot (memento) | Command with inverse |
| --- | --- | --- |
| Memory per step | O(document) | O(edit size) |
| Undo cost | O(document) | O(edit size) |
| Complexity | trivial | must define an inverse per operation |

For a real editor the document is far larger than any single edit, so **Command wins**. Say the tradeoff out loud, then implement Command.

**Structure.** Two stacks. Executing a new command pushes onto `undoStack` and clears `redoStack` — that clearing is the detail candidates forget, and it is what stops a redo from replaying against a diverged document.

```java
import java.util.*;

/** An edit that knows how to undo itself. */
interface Command {
    void execute(StringBuilder doc);
    void undo(StringBuilder doc);
}

class InsertCommand implements Command {
    private final int position;
    private final String text;

    InsertCommand(int position, String text) {
        this.position = position;
        this.text = text;
    }

    @Override public void execute(StringBuilder doc) { doc.insert(position, text); }

    @Override public void undo(StringBuilder doc) { doc.delete(position, position + text.length()); }
}

class DeleteCommand implements Command {
    private final int position;
    private final int length;
    private String removed;             // captured at execute time, needed to undo

    DeleteCommand(int position, int length) {
        this.position = position;
        this.length = length;
    }

    @Override public void execute(StringBuilder doc) {
        removed = doc.substring(position, position + length);
        doc.delete(position, position + length);
    }

    @Override public void undo(StringBuilder doc) { doc.insert(position, removed); }
}

/** Composite: several edits that undo as one unit (e.g. replace = delete + insert). */
class CompositeCommand implements Command {
    private final List<Command> parts;

    CompositeCommand(List<Command> parts) { this.parts = List.copyOf(parts); }

    @Override public void execute(StringBuilder doc) {
        for (Command c : parts) c.execute(doc);
    }

    @Override public void undo(StringBuilder doc) {
        for (int i = parts.size() - 1; i >= 0; i--) parts.get(i).undo(doc);   // reverse order
    }
}

class TextEditor {
    private final StringBuilder doc = new StringBuilder();
    private final Deque<Command> undoStack = new ArrayDeque<>();
    private final Deque<Command> redoStack = new ArrayDeque<>();
    private final int historyLimit;

    public TextEditor(int historyLimit) { this.historyLimit = historyLimit; }

    public String text() { return doc.toString(); }

    public int length() { return doc.length(); }

    public void insert(int position, String text) {
        checkPosition(position, 0);
        apply(new InsertCommand(position, text));
    }

    public void delete(int position, int length) {
        checkPosition(position, length);
        apply(new DeleteCommand(position, length));
    }

    public void replace(int position, int length, String text) {
        checkPosition(position, length);
        apply(new CompositeCommand(List.of(
            new DeleteCommand(position, length),
            new InsertCommand(position, text))));
    }

    private void apply(Command command) {
        command.execute(doc);
        undoStack.push(command);
        redoStack.clear();                     // a new edit invalidates the redo branch
        if (undoStack.size() > historyLimit) undoStack.removeLast();   // drop the oldest
    }

    public boolean canUndo() { return !undoStack.isEmpty(); }
    public boolean canRedo() { return !redoStack.isEmpty(); }

    public void undo() {
        if (undoStack.isEmpty()) return;
        Command c = undoStack.pop();
        c.undo(doc);
        redoStack.push(c);
    }

    public void redo() {
        if (redoStack.isEmpty()) return;
        Command c = redoStack.pop();
        c.execute(doc);
        undoStack.push(c);
    }

    private void checkPosition(int position, int length) {
        if (position < 0 || position + length > doc.length()) {
            throw new IndexOutOfBoundsException("position " + position + " length " + length);
        }
    }
}
```

**Extensions.**

- *Coalescing typed characters* → before pushing, check whether the top of `undoStack` is an `InsertCommand` ending exactly where this one begins and within a time window; if so, merge them. Otherwise every keystroke is its own undo step, which users hate.
- *Cursor and selection restoration* → undo should also restore where the caret was. Store the pre-edit cursor position in each command and restore it on `undo`.
- *Very large documents* → `StringBuilder` insert/delete is O(n) because of the array copy. A rope or gap buffer makes edits O(log n) / amortized O(1). The `Command` layer does not change — only the buffer behind it does, which is a nice demonstration that the abstraction is at the right level.
- *Collaborative editing* → this is where commands stop being enough; you need operational transformation or CRDTs to reconcile concurrent edits. Correctly scoping that as out of bounds for an OOD round is a good answer.

**Concurrency.** A single document with one editing thread; the UI thread and the edit thread are separated by a queue. If you truly need multi-threaded edits on one buffer, position-based commands become invalid the moment another thread edits earlier in the document — which is exactly why collaborative editors use OT/CRDT rather than locks.

### 7. Design an Expense-Sharing App (Splitwise)

**Problem.** Users share expenses in groups. An expense is paid by one person and split among several — equally, by exact amounts, or by percentage. Report who owes whom.

**Clarify first.** Do we settle within groups or globally? Do we need multi-currency? Should we *simplify* debts (A owes B, B owes C becomes A owes C)? — Assume: global balances, single currency, simplification asked as a follow-up.

**Key decision.** Do not store a debt edge per expense — that grows without bound and makes queries slow. Store a **net balance per pair** in a `Map<payer, Map<owed, amount>>` and keep it antisymmetric: crediting `A -> B` always debits `B -> A`. Every query is then O(1) lookup, and "simplify" becomes a well-defined graph problem over net positions.

**Money.** Use `long` cents, never `double`. Splitting 100 cents three ways must total 100, so the remainder is distributed one cent at a time — the interviewer will check for this.

```java
import java.util.*;

enum SplitType { EQUAL, EXACT, PERCENT }

record User(String id, String name) {
    @Override public boolean equals(Object o) {
        return o instanceof User u && id.equals(u.id);
    }
    @Override public int hashCode() { return id.hashCode(); }
}

/** How an expense is divided. @return per-participant amounts in cents, summing exactly to total. */
interface SplitStrategy {
    Map<String, Long> split(long totalCents, List<String> participants, List<Long> parameters);
}

class EqualSplit implements SplitStrategy {
    @Override
    public Map<String, Long> split(long totalCents, List<String> participants, List<Long> ignored) {
        int n = participants.size();
        long base = totalCents / n;
        long remainder = totalCents - base * n;          // spread the leftover cents

        Map<String, Long> shares = new LinkedHashMap<>();
        for (int i = 0; i < n; i++) {
            shares.put(participants.get(i), base + (i < remainder ? 1 : 0));
        }
        return shares;
    }
}

class ExactSplit implements SplitStrategy {
    @Override
    public Map<String, Long> split(long totalCents, List<String> participants, List<Long> amounts) {
        if (amounts.size() != participants.size()) {
            throw new IllegalArgumentException("one amount per participant required");
        }
        long sum = amounts.stream().mapToLong(Long::longValue).sum();
        if (sum != totalCents) {
            throw new IllegalArgumentException("exact amounts must sum to " + totalCents);
        }
        Map<String, Long> shares = new LinkedHashMap<>();
        for (int i = 0; i < participants.size(); i++) shares.put(participants.get(i), amounts.get(i));
        return shares;
    }
}

class PercentSplit implements SplitStrategy {
    @Override
    public Map<String, Long> split(long totalCents, List<String> participants, List<Long> percents) {
        if (percents.size() != participants.size()) {
            throw new IllegalArgumentException("one percent per participant required");
        }
        long sum = percents.stream().mapToLong(Long::longValue).sum();
        if (sum != 100) throw new IllegalArgumentException("percents must sum to 100");

        Map<String, Long> shares = new LinkedHashMap<>();
        long assigned = 0;
        for (int i = 0; i < participants.size(); i++) {
            long share = i == participants.size() - 1
                ? totalCents - assigned                   // last one absorbs rounding
                : totalCents * percents.get(i) / 100;
            shares.put(participants.get(i), share);
            assigned += share;
        }
        return shares;
    }
}

record Expense(String id, String description, long amountCents,
               String paidByUserId, Map<String, Long> shares) {}

class ExpenseManager {
    private final Map<String, User> users = new HashMap<>();
    private final List<Expense> expenses = new ArrayList<>();
    /** balances.get(a).get(b) > 0  means  a is owed that much by b. */
    private final Map<String, Map<String, Long>> balances = new HashMap<>();

    private final Map<SplitType, SplitStrategy> strategies = Map.of(
        SplitType.EQUAL,   new EqualSplit(),
        SplitType.EXACT,   new ExactSplit(),
        SplitType.PERCENT, new PercentSplit());

    public void addUser(User user) {
        users.put(user.id(), user);
        balances.putIfAbsent(user.id(), new HashMap<>());
    }

    public Expense addExpense(String description, long amountCents, String paidBy,
                              List<String> participants, SplitType type, List<Long> parameters) {
        if (!users.containsKey(paidBy)) throw new IllegalArgumentException("unknown payer " + paidBy);
        if (amountCents <= 0) throw new IllegalArgumentException("amount must be positive");

        Map<String, Long> shares = strategies.get(type).split(amountCents, participants, parameters);

        for (Map.Entry<String, Long> e : shares.entrySet()) {
            String debtor = e.getKey();
            if (debtor.equals(paidBy)) continue;            // the payer owes themselves nothing
            credit(paidBy, debtor, e.getValue());
        }

        Expense expense = new Expense(UUID.randomUUID().toString(), description,
                                      amountCents, paidBy, shares);
        expenses.add(expense);
        return expense;
    }

    /**
     * Record a repayment: {@code fromUserId} hands {@code amountCents} to {@code toUserId},
     * which cancels that much of what they owed.
     */
    public void settle(String fromUserId, String toUserId, long amountCents) {
        credit(fromUserId, toUserId, amountCents);
    }

    /** creditor is owed {@code amount} more by debtor; keeps the matrix antisymmetric. */
    private void credit(String creditor, String debtor, long amount) {
        balances.computeIfAbsent(creditor, k -> new HashMap<>()).merge(debtor, amount, Long::sum);
        balances.computeIfAbsent(debtor, k -> new HashMap<>()).merge(creditor, -amount, Long::sum);
    }

    /** Positive = others owe this user; negative = this user owes others. */
    public long netBalanceOf(String userId) {
        return balances.getOrDefault(userId, Map.of())
                       .values().stream().mapToLong(Long::longValue).sum();
    }

    /** Non-zero pairwise debts involving this user. */
    public Map<String, Long> balancesOf(String userId) {
        Map<String, Long> out = new LinkedHashMap<>();
        balances.getOrDefault(userId, Map.of()).forEach((other, amount) -> {
            if (amount != 0) out.put(other, amount);
        });
        return out;
    }

    /**
     * Minimize the number of transactions that settle everyone.
     * Greedy max-debtor / max-creditor matching: each step zeroes at least one
     * person, so it uses at most n-1 transfers. (The true minimum is NP-hard;
     * this is the standard heuristic and is optimal in the common cases.)
     */
    public List<String> simplifyDebts() {
        Map<String, Long> net = new HashMap<>();
        for (String id : users.keySet()) net.put(id, netBalanceOf(id));

        PriorityQueue<Map.Entry<String, Long>> creditors =
            new PriorityQueue<>((a, b) -> Long.compare(b.getValue(), a.getValue()));
        PriorityQueue<Map.Entry<String, Long>> debtors =
            new PriorityQueue<>(Map.Entry.comparingByValue());

        net.forEach((id, amount) -> {
            if (amount > 0) creditors.offer(Map.entry(id, amount));
            else if (amount < 0) debtors.offer(Map.entry(id, amount));
        });

        List<String> transfers = new ArrayList<>();
        while (!creditors.isEmpty() && !debtors.isEmpty()) {
            var creditor = creditors.poll();
            var debtor = debtors.poll();

            long amount = Math.min(creditor.getValue(), -debtor.getValue());
            transfers.add(debtor.getKey() + " pays " + creditor.getKey() + " " + amount + " cents");

            long creditorLeft = creditor.getValue() - amount;
            long debtorLeft = debtor.getValue() + amount;
            if (creditorLeft > 0) creditors.offer(Map.entry(creditor.getKey(), creditorLeft));
            if (debtorLeft < 0) debtors.offer(Map.entry(debtor.getKey(), debtorLeft));
        }
        return transfers;
    }
}
```

**Extensions.**

- *Groups* → a `Group` entity holding a member list; expenses carry an optional `groupId` and balances are keyed by `(groupId, userId)` pairs. Global settlement then means collapsing across groups.
- *Multi-currency* → store the currency alongside every amount and convert at expense time using a `ExchangeRateProvider`. Never store mixed-currency balances in one number.
- *Editing or deleting an expense* → because balances are aggregates, you must apply the inverse of the original expense before applying the new one. Keeping the immutable `Expense` list is what makes that possible, and it is the reason not to discard the log even though balances are derived.
- *Audit / history* → the `expenses` list is already an event log; balances are a materialized view over it. Worth naming — it is the same event-sourcing idea, at small scale.

**Concurrency.** Two expenses touching the same pair race on the balance cell. Options in ascending order of scale: `synchronized` on the manager (fine for one process), `ConcurrentHashMap` with `merge` (atomic per cell, but a single expense updates several cells and is not atomic overall), or a per-user lock ordered by user id to avoid deadlock. The honest answer at L4: a real system makes each expense a database transaction.

### 8. Design an In-Memory Key-Value Store with TTL

**Problem.** `put(key, value)`, `put(key, value, ttl)`, `get(key)`, `delete(key)`. Expired keys must be invisible and must not leak memory.

**Clarify first.** Is a bounded size needed, or just TTL? Must `get` on an expired key be O(1)? Do we need atomic compare-and-set? — Assume: TTL plus optional max size, O(1) reads, single process.

**Key decision — and the reason this question is asked.** There are two expiry mechanisms and a correct answer uses **both**:

- **Lazy expiry** — check the timestamp on read. O(1), zero background cost, but a key written once and never read again occupies memory forever.
- **Active expiry** — a background sweep. Reclaims memory, but must not scan every key on every tick.

Combining them gives correct reads immediately and bounded memory eventually. A `PriorityQueue` ordered by expiry time makes the sweep O(log n) per evicted key instead of O(n) per tick.

**Stale-entry trap.** If a key is overwritten with a new TTL, the old heap entry is now wrong. Do **not** try to remove it — `PriorityQueue.remove(Object)` is O(n). Instead let it sit and validate on pop: compare the heap entry's expiry against the map's current expiry and skip if they differ. This is lazy deletion, the same technique as the heap solutions in `26U/0.nc150-java.md`.

```java
import java.util.*;
import java.util.concurrent.locks.ReentrantLock;

class TtlKeyValueStore<K, V> {

    private static final class Entry<V> {
        final V value;
        final long expiresAtMillis;      // Long.MAX_VALUE == never

        Entry(V value, long expiresAtMillis) {
            this.value = value;
            this.expiresAtMillis = expiresAtMillis;
        }

        boolean isExpired(long now) { return now >= expiresAtMillis; }
    }

    private record ExpiryRef<K>(K key, long expiresAtMillis) {}

    private final Map<K, Entry<V>> map = new HashMap<>();
    private final PriorityQueue<ExpiryRef<K>> expiryQueue =
        new PriorityQueue<>(Comparator.comparingLong(ExpiryRef::expiresAtMillis));
    private final ReentrantLock lock = new ReentrantLock();
    private final Clock clock;

    /** Injected so tests can advance time without sleeping. */
    public interface Clock { long nowMillis(); }

    public TtlKeyValueStore() { this(System::currentTimeMillis); }

    public TtlKeyValueStore(Clock clock) { this.clock = clock; }

    public void put(K key, V value) {
        lock.lock();
        try {
            map.put(key, new Entry<>(value, Long.MAX_VALUE));
        } finally {
            lock.unlock();
        }
    }

    public void put(K key, V value, long ttlMillis) {
        if (ttlMillis <= 0) throw new IllegalArgumentException("ttl must be positive");
        long expiresAt = clock.nowMillis() + ttlMillis;

        lock.lock();
        try {
            map.put(key, new Entry<>(value, expiresAt));
            // A previous ExpiryRef for this key may still be queued; that is fine,
            // it is validated against the map when popped.
            expiryQueue.offer(new ExpiryRef<>(key, expiresAt));
        } finally {
            lock.unlock();
        }
    }

    /** Lazy expiry: an expired key is removed on read and reported absent. */
    public Optional<V> get(K key) {
        lock.lock();
        try {
            Entry<V> entry = map.get(key);
            if (entry == null) return Optional.empty();
            if (entry.isExpired(clock.nowMillis())) {
                map.remove(key);
                return Optional.empty();
            }
            return Optional.of(entry.value);
        } finally {
            lock.unlock();
        }
    }

    public boolean delete(K key) {
        lock.lock();
        try {
            return map.remove(key) != null;
        } finally {
            lock.unlock();
        }
    }

    /**
     * Active expiry: call from a scheduled thread. Only touches keys that have
     * actually expired, so the cost is O(evicted * log n), not O(size).
     * @return how many keys were reclaimed.
     */
    public int evictExpired() {
        long now = clock.nowMillis();
        int removed = 0;

        lock.lock();
        try {
            while (!expiryQueue.isEmpty() && expiryQueue.peek().expiresAtMillis() <= now) {
                ExpiryRef<K> ref = expiryQueue.poll();
                Entry<V> current = map.get(ref.key());

                // Stale reference: the key was overwritten with a different expiry.
                if (current == null || current.expiresAtMillis != ref.expiresAtMillis()) continue;

                map.remove(ref.key());
                removed++;
            }
            return removed;
        } finally {
            lock.unlock();
        }
    }

    /** Live key count. O(n) because it must skip lazily-expired entries. */
    public int size() {
        long now = clock.nowMillis();
        lock.lock();
        try {
            int count = 0;
            for (Entry<V> e : map.values()) if (!e.isExpired(now)) count++;
            return count;
        } finally {
            lock.unlock();
        }
    }
}
```

**Extensions.**

- *Bounded size with LRU eviction* → compose this with the `LRUCache` from `26U/0.nc150-java.md#lc-0146`. TTL and LRU are orthogonal: TTL decides *validity*, LRU decides *which valid entry to sacrifice*.
- *Atomic compare-and-set* → `boolean compareAndSet(K, V expected, V update)` inside the same lock. Trivial here, and it is what callers actually need to build a distributed lock on top.
- *Persistence* → an append-only log of operations plus periodic snapshots — Redis's AOF/RDB split, which is a good thing to name.
- *Sharding to reduce contention* → `n` independent stores selected by `key.hashCode() % n`, so unrelated keys never contend. This is exactly what `ConcurrentHashMap` does internally.

**Concurrency.** One `ReentrantLock` is correct and simple; note that it serializes reads, which is the obvious first bottleneck. The upgrades, in order: `ReadWriteLock` (many readers, one writer — though lazy expiry *mutates* on read, so `get` needs care or must defer removal), then `ConcurrentHashMap` with expiry checked on read and no global lock, then sharding. Being able to name why lazy expiry complicates a read-write lock is the L4 signal here.

### 9. Design a Rate Limiter

**Problem.** Allow at most `n` requests per client per time window. Reject or delay the rest.

**Clarify first.** Per client or global? Hard window or smooth? Do bursts need to be allowed? Single process or distributed? — Assume: per client, single process, and the interviewer will ask you to compare algorithms.

**Key decision.** The comparison *is* the question. Know all four:

| Algorithm | Memory per client | Burst behaviour | Flaw |
| --- | --- | --- | --- |
| **Fixed window** | O(1) | allows 2n at a window boundary | the boundary spike |
| **Sliding window log** | O(n) | exact | memory grows with the limit |
| **Sliding window counter** | O(1) | approximate | assumes uniform arrival in the previous window |
| **Token bucket** | O(1) | allows a controlled burst up to capacity | needs a refill rate *and* a capacity |

Token bucket is the usual production answer because it is O(1) and burst behaviour is a tunable rather than a bug. Put them all behind one interface so swapping is a config change.

```java
import java.util.*;
import java.util.concurrent.ConcurrentHashMap;

interface RateLimiter {
    /** @return true if the request is allowed right now. */
    boolean allow(String clientId);
}

/** Injected so tests can advance time without sleeping. */
interface MillisClock { long nowMillis(); }

/** Simplest, and the one with the boundary flaw: 2n requests can slip through. */
class FixedWindowRateLimiter implements RateLimiter {
    private record Window(long windowStart, int count) {}

    private final int limit;
    private final long windowMillis;
    private final Map<String, Window> windows = new ConcurrentHashMap<>();
    private final MillisClock clock;

    FixedWindowRateLimiter(int limit, long windowMillis, MillisClock clock) {
        this.limit = limit;
        this.windowMillis = windowMillis;
        this.clock = clock;
    }

    @Override
    public boolean allow(String clientId) {
        long now = clock.nowMillis();
        long currentStart = now - (now % windowMillis);

        Window updated = windows.compute(clientId, (k, w) -> {
            if (w == null || w.windowStart() != currentStart) return new Window(currentStart, 1);
            return new Window(currentStart, w.count() + 1);
        });
        return updated.count() <= limit;
    }
}

/** Exact, at the cost of storing every timestamp inside the window. */
class SlidingWindowLogRateLimiter implements RateLimiter {
    private final int limit;
    private final long windowMillis;
    private final Map<String, Deque<Long>> log = new ConcurrentHashMap<>();
    private final MillisClock clock;

    SlidingWindowLogRateLimiter(int limit, long windowMillis, MillisClock clock) {
        this.limit = limit;
        this.windowMillis = windowMillis;
        this.clock = clock;
    }

    @Override
    public boolean allow(String clientId) {
        long now = clock.nowMillis();
        Deque<Long> timestamps = log.computeIfAbsent(clientId, k -> new ArrayDeque<>());

        synchronized (timestamps) {
            while (!timestamps.isEmpty() && timestamps.peekFirst() <= now - windowMillis) {
                timestamps.pollFirst();                  // drop everything outside the window
            }
            if (timestamps.size() >= limit) return false;
            timestamps.offerLast(now);
            return true;
        }
    }
}

/**
 * O(1) and smooth: interpolate the previous window's count by how much of it
 * still overlaps the sliding window. Approximate — it assumes requests were
 * spread evenly across the previous window.
 */
class SlidingWindowCounterRateLimiter implements RateLimiter {
    private static final class Counter {
        long windowStart;
        int currentCount;
        int previousCount;
    }

    private final int limit;
    private final long windowMillis;
    private final Map<String, Counter> counters = new ConcurrentHashMap<>();
    private final MillisClock clock;

    SlidingWindowCounterRateLimiter(int limit, long windowMillis, MillisClock clock) {
        this.limit = limit;
        this.windowMillis = windowMillis;
        this.clock = clock;
    }

    @Override
    public boolean allow(String clientId) {
        long now = clock.nowMillis();
        long currentStart = now - (now % windowMillis);
        Counter c = counters.computeIfAbsent(clientId, k -> new Counter());

        synchronized (c) {
            if (c.windowStart != currentStart) {
                c.previousCount = c.windowStart == currentStart - windowMillis ? c.currentCount : 0;
                c.currentCount = 0;
                c.windowStart = currentStart;
            }
            double overlap = 1.0 - (double) (now - currentStart) / windowMillis;
            double estimated = c.previousCount * overlap + c.currentCount;

            if (estimated >= limit) return false;
            c.currentCount++;
            return true;
        }
    }
}

/**
 * Production default. Tokens refill continuously at {@code refillPerSecond};
 * a client may burst up to {@code capacity}. Lazy refill on access means no
 * background thread and O(1) memory per client.
 */
class TokenBucketRateLimiter implements RateLimiter {
    private static final class Bucket {
        double tokens;
        long lastRefillMillis;
    }

    private final double capacity;
    private final double refillPerMilli;
    private final Map<String, Bucket> buckets = new ConcurrentHashMap<>();
    private final MillisClock clock;

    TokenBucketRateLimiter(double capacity, double refillPerSecond, MillisClock clock) {
        this.capacity = capacity;
        this.refillPerMilli = refillPerSecond / 1000.0;
        this.clock = clock;
    }

    @Override
    public boolean allow(String clientId) {
        long now = clock.nowMillis();
        Bucket b = buckets.computeIfAbsent(clientId, k -> {
            Bucket fresh = new Bucket();
            fresh.tokens = capacity;
            fresh.lastRefillMillis = now;
            return fresh;
        });

        synchronized (b) {
            long elapsed = now - b.lastRefillMillis;
            if (elapsed > 0) {
                b.tokens = Math.min(capacity, b.tokens + elapsed * refillPerMilli);
                b.lastRefillMillis = now;
            }
            if (b.tokens < 1.0) return false;
            b.tokens -= 1.0;
            return true;
        }
    }
}
```

**Extensions.**

- *Distributed* → the state must move to Redis, and the check-then-increment must be atomic. Either a Lua script or `INCR` plus `EXPIRE` on a fixed-window key. Say the words "the read-modify-write must be atomic across nodes" — that is the crux.
- *Tiered limits* (per user, per IP, per endpoint) → a composite limiter that requires all sub-limiters to allow. Compose, do not add parameters.
- *Delay instead of reject* → the token bucket already tells you *when* the next token arrives, so `Retry-After` falls out of `(1 - tokens) / refillRate`.
- *Memory growth from idle clients* → per-client state must itself expire. This is the TTL store from question 8, which is why the two questions pair well.

**Concurrency.** Locking per client (on the bucket object) rather than globally is the key point: unrelated clients never contend. `computeIfAbsent` makes bucket creation atomic; a bare `containsKey`-then-`put` would let two threads create two buckets and lose half the accounting.

### 10. Design a Library Management System

**Problem.** Members borrow and return physical books. Track availability, due dates, fines, and holds.

**Clarify first.** Do we distinguish a *title* from a *physical copy*? How many books per member? Are reservations/holds in scope? Digital items? — Assume: titles with multiple copies, per-member borrow limit, holds in scope, physical only.

**Key decision.** The modelling trap is conflating `Book` (the title — ISBN, author, subject) with `BookCopy` (the physical item — barcode, condition, which branch). Members borrow *copies*; they search for and place holds on *titles*. Getting this split right is most of the grade on this question.

**Second decision.** Separate the **catalogue** (search) from the **lending** (loans, fines, holds). They change for different reasons — single responsibility made concrete.

```java
import java.time.LocalDate;
import java.time.temporal.ChronoUnit;
import java.util.*;

enum CopyStatus { AVAILABLE, LOANED, ON_HOLD_SHELF, LOST, DAMAGED }

/** The bibliographic record — one per ISBN. */
record Book(String isbn, String title, String author, String subject, int publicationYear) {}

/** A physical item on a shelf — many per Book. */
class BookCopy {
    private final String barcode;
    private final String isbn;
    private CopyStatus status = CopyStatus.AVAILABLE;

    BookCopy(String barcode, String isbn) {
        this.barcode = barcode;
        this.isbn = isbn;
    }

    String barcode() { return barcode; }
    String isbn() { return isbn; }
    CopyStatus status() { return status; }
    void setStatus(CopyStatus status) { this.status = status; }
}

record Member(String id, String name, LocalDate joinedOn) {}

class Loan {
    private final String copyBarcode;
    private final String memberId;
    private final LocalDate borrowedOn;
    private LocalDate dueOn;
    private LocalDate returnedOn;
    private int renewalCount;

    Loan(String copyBarcode, String memberId, LocalDate borrowedOn, LocalDate dueOn) {
        this.copyBarcode = copyBarcode;
        this.memberId = memberId;
        this.borrowedOn = borrowedOn;
        this.dueOn = dueOn;
    }

    String copyBarcode() { return copyBarcode; }
    String memberId() { return memberId; }
    LocalDate dueOn() { return dueOn; }
    LocalDate returnedOn() { return returnedOn; }
    int renewalCount() { return renewalCount; }
    boolean isOpen() { return returnedOn == null; }

    void renew(LocalDate newDue) {
        dueOn = newDue;
        renewalCount++;
    }

    void close(LocalDate on) { returnedOn = on; }

    long daysOverdue(LocalDate asOf) {
        LocalDate end = returnedOn != null ? returnedOn : asOf;
        long days = ChronoUnit.DAYS.between(dueOn, end);
        return Math.max(0, days);
    }
}

/** Fine rules change often — keep them injectable. */
interface FinePolicy {
    long fineInCents(Loan loan, LocalDate asOf);
}

class DailyFinePolicy implements FinePolicy {
    private final long centsPerDay;
    private final long maxCents;

    DailyFinePolicy(long centsPerDay, long maxCents) {
        this.centsPerDay = centsPerDay;
        this.maxCents = maxCents;
    }

    @Override
    public long fineInCents(Loan loan, LocalDate asOf) {
        return Math.min(maxCents, loan.daysOverdue(asOf) * centsPerDay);
    }
}

/** Search lives here, and only here. */
class Catalog {
    private final Map<String, Book> booksByIsbn = new HashMap<>();
    private final Map<String, Set<String>> byAuthor = new HashMap<>();
    private final Map<String, Set<String>> bySubject = new HashMap<>();
    private final Map<String, List<BookCopy>> copiesByIsbn = new HashMap<>();

    public void addBook(Book book) {
        booksByIsbn.put(book.isbn(), book);
        byAuthor.computeIfAbsent(book.author().toLowerCase(), k -> new HashSet<>()).add(book.isbn());
        bySubject.computeIfAbsent(book.subject().toLowerCase(), k -> new HashSet<>()).add(book.isbn());
    }

    public void addCopy(BookCopy copy) {
        if (!booksByIsbn.containsKey(copy.isbn())) {
            throw new IllegalArgumentException("no such title: " + copy.isbn());
        }
        copiesByIsbn.computeIfAbsent(copy.isbn(), k -> new ArrayList<>()).add(copy);
    }

    public Optional<Book> byIsbn(String isbn) { return Optional.ofNullable(booksByIsbn.get(isbn)); }

    public List<Book> searchByAuthor(String author) { return lookup(byAuthor, author); }

    public List<Book> searchBySubject(String subject) { return lookup(bySubject, subject); }

    private List<Book> lookup(Map<String, Set<String>> index, String rawKey) {
        List<Book> out = new ArrayList<>();
        for (String isbn : index.getOrDefault(rawKey.toLowerCase(), Set.of())) {
            out.add(booksByIsbn.get(isbn));
        }
        return out;
    }

    Optional<BookCopy> findAvailableCopy(String isbn) {
        return copiesByIsbn.getOrDefault(isbn, List.of()).stream()
            .filter(c -> c.status() == CopyStatus.AVAILABLE)
            .findFirst();
    }

    Optional<BookCopy> byBarcode(String barcode) {
        return copiesByIsbn.values().stream()
            .flatMap(List::stream)
            .filter(c -> c.barcode().equals(barcode))
            .findFirst();
    }
}

/** Loans, holds and fines live here — separate from search. */
class LendingService {
    private final Catalog catalog;
    private final FinePolicy finePolicy;
    private final int maxBooksPerMember;
    private final int loanDays;
    private final int maxRenewals;

    private final Map<String, Member> members = new HashMap<>();
    private final Map<String, Loan> openLoanByBarcode = new HashMap<>();
    private final Map<String, List<Loan>> loansByMember = new HashMap<>();
    private final Map<String, Deque<String>> holdQueueByIsbn = new HashMap<>();
    private final Map<String, Long> outstandingFines = new HashMap<>();

    public LendingService(Catalog catalog, FinePolicy finePolicy,
                          int maxBooksPerMember, int loanDays, int maxRenewals) {
        this.catalog = catalog;
        this.finePolicy = finePolicy;
        this.maxBooksPerMember = maxBooksPerMember;
        this.loanDays = loanDays;
        this.maxRenewals = maxRenewals;
    }

    public void register(Member member) { members.put(member.id(), member); }

    public Loan borrow(String memberId, String isbn, LocalDate today) {
        requireMember(memberId);
        if (openLoanCount(memberId) >= maxBooksPerMember) {
            throw new IllegalStateException("borrow limit reached");
        }
        Deque<String> holds = holdQueueByIsbn.get(isbn);
        if (holds != null && !holds.isEmpty() && !holds.peekFirst().equals(memberId)) {
            throw new IllegalStateException("title is reserved for another member");
        }

        BookCopy copy = catalog.findAvailableCopy(isbn)
            .orElseThrow(() -> new IllegalStateException("no available copy of " + isbn));

        copy.setStatus(CopyStatus.LOANED);
        if (holds != null && !holds.isEmpty()) holds.pollFirst();   // hold fulfilled

        Loan loan = new Loan(copy.barcode(), memberId, today, today.plusDays(loanDays));
        openLoanByBarcode.put(copy.barcode(), loan);
        loansByMember.computeIfAbsent(memberId, k -> new ArrayList<>()).add(loan);
        return loan;
    }

    /** @return the fine charged in cents. */
    public long returnCopy(String barcode, LocalDate today) {
        Loan loan = openLoanByBarcode.remove(barcode);
        if (loan == null) throw new IllegalArgumentException("no open loan for " + barcode);

        loan.close(today);
        long fine = finePolicy.fineInCents(loan, today);
        if (fine > 0) outstandingFines.merge(loan.memberId(), fine, Long::sum);

        BookCopy copy = catalog.byBarcode(barcode).orElseThrow();
        Deque<String> holds = holdQueueByIsbn.get(copy.isbn());
        copy.setStatus(holds != null && !holds.isEmpty()
            ? CopyStatus.ON_HOLD_SHELF          // reserved for the next member in line
            : CopyStatus.AVAILABLE);
        return fine;
    }

    public void renew(String barcode, LocalDate today) {
        Loan loan = openLoanByBarcode.get(barcode);
        if (loan == null) throw new IllegalArgumentException("no open loan for " + barcode);
        if (loan.renewalCount() >= maxRenewals) throw new IllegalStateException("renewal limit reached");

        BookCopy copy = catalog.byBarcode(barcode).orElseThrow();
        Deque<String> holds = holdQueueByIsbn.get(copy.isbn());
        if (holds != null && !holds.isEmpty()) throw new IllegalStateException("others are waiting");

        loan.renew(today.plusDays(loanDays));
    }

    /** FIFO waiting list on a title, not a copy. */
    public int placeHold(String memberId, String isbn) {
        requireMember(memberId);
        Deque<String> queue = holdQueueByIsbn.computeIfAbsent(isbn, k -> new ArrayDeque<>());
        if (queue.contains(memberId)) throw new IllegalStateException("hold already placed");
        queue.offerLast(memberId);
        return queue.size();                     // position in line
    }

    public List<Loan> overdueLoans(LocalDate today) {
        List<Loan> out = new ArrayList<>();
        for (Loan loan : openLoanByBarcode.values()) {
            if (today.isAfter(loan.dueOn())) out.add(loan);
        }
        return out;
    }

    public long finesOwedBy(String memberId) { return outstandingFines.getOrDefault(memberId, 0L); }

    private int openLoanCount(String memberId) {
        return (int) loansByMember.getOrDefault(memberId, List.of()).stream()
            .filter(Loan::isOpen).count();
    }

    private void requireMember(String memberId) {
        if (!members.containsKey(memberId)) throw new IllegalArgumentException("unknown member");
    }
}
```

**Extensions.**

- *Multiple branches* → `BookCopy` gains a `branchId`; search becomes "which branches have this available"; inter-branch transfers become their own workflow with a copy status of `IN_TRANSIT`.
- *E-books and audiobooks* → the borrow/return contract is the same, but there is no physical copy and no fine, so lift `Borrowable` into an interface and let `PhysicalCopy` and `DigitalLicense` implement it. Concurrent-licence limits replace copy counts.
- *Hold expiry* → a copy sitting in `ON_HOLD_SHELF` must return to `AVAILABLE` after a few days, which is the TTL pattern from question 8 again.
- *Notifications* (due soon, hold ready) → Observer. `LendingService` publishes events; `EmailNotifier` and `SmsNotifier` subscribe. Do not put email code inside `returnCopy`.
- *Full-text search* → the hand-rolled inverted indexes in `Catalog` are a stand-in for a real search engine. Saying "this is where you'd put Lucene/Elasticsearch and stop hand-rolling indexes" is the right instinct.

**Concurrency.** Two members borrowing the last copy at once is the classic race: `findAvailableCopy` then `setStatus` is a check-then-act that needs to be atomic. Options: synchronize per ISBN (fine-grained, unrelated titles proceed in parallel), or make copy status an `AtomicReference` and use `compareAndSet(AVAILABLE, LOANED)` so exactly one thread wins. The second is the better answer — it is lock-free and the loser simply retries with the next copy.
