## 1. OCI physical topology

```
Realm (e.g. commercial OC1)
 └─ Region (geo area)
     └─ Availability Domain (AD) = 1+ isolated data centers
         └─ Fault Domain (FD) ×3 = separate hardware/power within an AD
```

- Realm
  → Isolated collection of regions; no data shared across realms
  → Your tenancy lives in exactly one realm (commercial, government, dedicated)
- Region
  → One or more ADs; regional resources (VCN, Certificates, LB) live here
  → Multi-region = DR; must duplicate regional resources
- Availability Domain
  → Independent power/cooling/network; failure of one AD shouldn't touch another
  → Some regions have 1 AD (then rely on FDs + cross-region)
- Fault Domain
  → Three per AD; anti-affinity for hardware failure + maintenance
  → Lower latency between FDs than between ADs
- 🗣 Design one-liner: "FDs for hardware blast radius, ADs for facility blast radius, regions for geographic DR."
- Defeater: AD isolation is a facility property, not a software one — a control-plane bug can still hit all ADs

## 2. Control plane vs data plane

```
control plane [control plane]   data plane [hot path]
 create/update/delete resource   serve runtime traffic
 work requests, async, audited   must survive control-plane outage
```

- Control plane
  → Handles resource lifecycle: create/update/delete, config, membership
  → Async "work requests" — API returns 202-style handle, poll for state
  → Audited (every admin action logged)
- Data plane
  → Serves the actual traffic (TLS termination, packets, reads/writes)
  → **Static stability**: keeps running on last-known-good config if control plane is down
- Why the split matters (say this in SD)
  → Different SLAs: control plane 99.9x, data plane 99.99+
  → Different scaling: control plane low QPS/high consistency; data plane high QPS/eventual ok
  → Blast radius: control-plane deploys shouldn't roll data-plane fleet
- Defeater: "static stability" breaks if data plane needs control plane on restart (e.g., fetch cert on boot with no local cache)
- Your anchor: JPMC platform = config/admin APIs (control) vs enrichment/serving (data); name it that way

## 3. OCI Certificates service

```
Root CA ──► Subordinate CA ──► Leaf cert ──► LB / API Gateway / your service
   │            │                 │
 HSM key     HSM key         auto-rotation, versions, CRL
```

- What it is
  → Managed TLS certs, CAs, CA bundles; regional resource
  → CA hierarchy up to 10 levels deep
- Hierarchies
  → Single-tier: one CA is root + issuer — simpler, root key exposed to issuance
  → Two-tier: offline-ish root + subordinate issuing CA — root compromise blast radius contained
  → Leaf certs cannot sign
- Keys
  → CA private keys live in OCI Vault (HSM-backed); service never holds a copy
  → Chain can't mix key families: RSA chain vs ECDSA chain
- Lifecycle
  → Issue → store → **auto-renew/rotate** (versioned; PENDING → CURRENT → PREVIOUS/DEPRECATED)
  → Revoke via CRL (published; clients must fetch — defeater: stale CRL cache)
  → BYOCA: import external root by PEM; private key never uploaded
- Integrations
  → Load Balancer / API Gateway consume certs
  → IAM policies gate create/use; Audit records admin actions; Cloud Guard flags misconfig
- Interview angle
  → This is a control-plane service: low write QPS, high correctness, strict authz, audit
  → Data-plane consumers (LBs) must cache the cert and survive Certificates being down
  → Rotation = the hard part: two valid versions overlap; consumers switch without downtime

## 4. Oracle PKI legacy concepts (recruiter doc)

- Oracle Wallet
  → Container for certs, trust points (trusted CAs), private keys
  → Used by Oracle Database, SSL/TLS auth, WebLogic
- Oracle Wallet Manager (OWM): tool to create/manage wallets
- Trust point: a CA cert you choose to trust; chain validates up to it
- Mapping: wallet ≈ keystore/truststore; OCI Certificates ≈ cloud-native wallet + CA + rotation
- 🗣 "OCI Certificates is the managed evolution of the wallet model: same chain-of-trust, but keys in HSM and rotation automated."

## 5. TLS / PKI fundamentals you must explain in 60 seconds

- TLS 1.3 handshake
  → ClientHello (ciphers, key share) → ServerHello (key share, cert, finished) → client verifies chain, sends finished → app data
  → 1-RTT; 0-RTT optional (replay risk — defeater)
- Chain validation
  → Leaf signed by intermediate, signed by root in client truststore
  → Check: signature, validity dates, hostname (SAN), revocation (CRL/OCSP), key usage
- mTLS
  → Both sides present certs; service-to-service identity without shared secrets
  → Cost: cert distribution + rotation for every workload → this is why a Certificates service exists
- Rotation
  → Overlap window: new cert issued before old expires; consumers reload without restart
  → Failure: expired cert = hard outage (canonical pattern; many public postmortems)
- Revocation
  → CRL: periodic list; OCSP: online check; OCSP stapling: server attaches proof
  → Defeater: soft-fail clients accept when revocation check unreachable
- Your anchor: JPMC OAuth2/JWT + Spring Security; JWT validation sequence ≈ cert chain validation (issuer, signature, expiry, audience)

## 6. Recruiter's CS term list — one-liners + defeaters

| Term | One-liner | Defeater / edge |
|---|---|---|
| Horizontal vs vertical scaling | Add nodes vs bigger node | Horizontal needs statelessness or partitioning; vertical has a ceiling + single point |
| P50/P90/P99/P100 | Latency percentiles; P99 = tail | Averages hide tails; P100 = worst single request, noisy |
| SLA / SLO / SLI | Contract / target / measurement | SLA without an SLI you can measure is unenforceable |
| Availability | Fraction of time serving correctly | 99.99% = 52 min/yr; depends on dependency chain product |
| Durability | Data survives failures | Stated as "to N failures of what" — 3 replicas across FDs ≠ across ADs |
| Blast radius | Scope of impact when a thing fails | Reduce via cells, FDs, canaries, per-tenant isolation |
| System invariant | Property that must always hold (e.g., no cert issued without HSM signature) | Enforce mechanically, not by convention |
| Single point of failure | Component with no redundancy | Control plane, DNS, CA root are common hidden SPOFs |
| Exponential backoff | Retry with growing delay + jitter | Without jitter → thundering herd; need retry budget |
| Two-phase commit | Prepare then commit across participants | Blocking on coordinator failure; prefer sagas/outbox |
| Consensus / leader election | Agreement among nodes (Raft/Paxos) | Needs majority quorum; split brain if two leaders — use fencing tokens |
| Vector clock | Per-node counters to detect concurrent updates | Grows with nodes; detects conflict, doesn't resolve it |
| Eventual consistency | Replicas converge given no new writes | Read-your-writes not guaranteed; define staleness bound |
| Caching | Keep hot data close | Invalidation, stampede, stale reads; TTL by freshness class |
| Load balancer | Distribute + health-check | L4 vs L7; LB itself must be HA; sticky sessions break statelessness |

## 7. Java / OS / Linux quick-hit (reported discussion topics)

- Java
  → JVM memory: heap (young/old), metaspace, stack per thread; GC: G1 default, ZGC low-pause
  → HashMap: array of bins, hash → index, treeify at 8; Hashtable synchronized/legacy
  → ConcurrentHashMap: per-bin CAS/synchronized, no global lock; iterators weakly consistent
  → fail-fast (ArrayList iterator, CME) vs fail-safe (copy-on-write, concurrent collections)
  → `synchronized` vs `ReentrantLock` (tryLock, fairness, conditions); `volatile` = visibility, not atomicity
  → Executors: fixed vs cached vs virtual threads (Java 21); `CompletableFuture`
  → Checked vs unchecked; `finally` overrides `return`; interface default vs abstract class
  → StringBuilder (unsynchronized) vs StringBuffer
- OS
  → Process vs thread: address space vs shared heap + own stack
  → Virtual memory, paging, TLB; deadlock = 4 conditions, break by lock ordering
  → VM vs container: hypervisor + guest kernel vs shared kernel + namespaces/cgroups
- Linux
  → `grep -r`, `awk '{print $2}'`, `sort | uniq -c | sort -rn`, `tail -f`, `ps aux`, `top`, `netstat/ss`, `curl -v`, `openssl x509 -in cert.pem -text -noout`
- Networking
  → How ping works (ICMP echo); traceroute (TTL expiry); debugging packet drop hop by hop
