#### 295. [Find Median from Data Stream](https://leetcode.com/problems/find-median-from-data-stream/) [H]

Description: Maintain a running median as numbers are added.

Idea: Two heaps — a max-heap for the lower half, a min-heap for the upper half. Push into `small`, spill its top into `large` to enforce the ordering invariant, then rebalance so `small.size()` is either equal to or one greater than `large.size()`.

**Java note.** Python fakes a max-heap by negating every value. Java has a real one via `Collections.reverseOrder()`, so the negation and the sign-flipping arithmetic all disappear.

```java
class MedianFinder {
    private final PriorityQueue<Integer> small = new PriorityQueue<>(Collections.reverseOrder());
    private final PriorityQueue<Integer> large = new PriorityQueue<>();

    public MedianFinder() {}

    public void addNum(int num) {
        small.offer(num);
        large.offer(small.poll());                 // top of small moves over: keeps small <= large
        if (large.size() > small.size()) small.offer(large.poll());
    }

    public double findMedian() {
        if (small.size() > large.size()) return small.peek();
        return (small.peek() + large.peek()) / 2.0;
    }
}
// Time: O(log n) per insert, O(1) median, Space: O(n)
```

⚠️ `(small.peek() + large.peek()) / 2` would do integer division. The `2.0` is load-bearing.

#### 432. [All O`one Data Structure](https://leetcode.com/problems/all-oone-data-structure/) [H]

Description: Support `inc`, `dec`, `getMaxKey`, and `getMinKey`, all in O(1).

Idea: A doubly-linked list of **count buckets** kept in ascending count order, each holding the set of keys with that count, plus a map `key -> bucket`. Incrementing a key moves it to the adjacent bucket, creating that bucket only if it does not already exist. Because counts change by exactly one, the neighbour is always the only candidate — that is what makes it O(1) rather than O(log n).

**Java note.** Buckets use `LinkedHashSet` so `iterator().next()` is deterministic; Python's `set` iteration order is arbitrary, which is fine for the problem but harder to reason about.

```java
class AllOne {
    private static final class Bucket {
        final int count;
        final Set<String> keys = new LinkedHashSet<>();
        Bucket prev, next;

        Bucket(int count) { this.count = count; }
    }

    private final Bucket head = new Bucket(0);      // sentinel: lowest counts side
    private final Bucket tail = new Bucket(0);      // sentinel: highest counts side
    private final Map<String, Bucket> bucketOf = new HashMap<>();

    public AllOne() {
        head.next = tail;
        tail.prev = head;
    }

    private void insertAfter(Bucket node, Bucket fresh) {
        fresh.prev = node;
        fresh.next = node.next;
        node.next.prev = fresh;
        node.next = fresh;
    }

    private void unlink(Bucket node) {
        node.prev.next = node.next;
        node.next.prev = node.prev;
    }

    public void inc(String key) {
        Bucket cur = bucketOf.get(key);

        if (cur == null) {                          // new key, count becomes 1
            Bucket first = head.next;
            if (first == tail || first.count != 1) {
                first = new Bucket(1);
                insertAfter(head, first);
            }
            first.keys.add(key);
            bucketOf.put(key, first);
            return;
        }

        Bucket nxt = cur.next;
        if (nxt == tail || nxt.count != cur.count + 1) {
            nxt = new Bucket(cur.count + 1);
            insertAfter(cur, nxt);
        }
        nxt.keys.add(key);
        bucketOf.put(key, nxt);

        cur.keys.remove(key);
        if (cur.keys.isEmpty()) unlink(cur);
    }

    public void dec(String key) {
        Bucket cur = bucketOf.get(key);
        if (cur == null) return;

        if (cur.count == 1) {                       // drops to 0: key leaves entirely
            bucketOf.remove(key);
            cur.keys.remove(key);
            if (cur.keys.isEmpty()) unlink(cur);
            return;
        }

        Bucket prev = cur.prev;
        if (prev == head || prev.count != cur.count - 1) {
            prev = new Bucket(cur.count - 1);
            insertAfter(cur.prev, prev);
        }
        prev.keys.add(key);
        bucketOf.put(key, prev);

        cur.keys.remove(key);
        if (cur.keys.isEmpty()) unlink(cur);
    }

    public String getMaxKey() {
        Bucket b = tail.prev;
        return b == head ? "" : b.keys.iterator().next();
    }

    public String getMinKey() {
        Bucket b = head.next;
        return b == tail ? "" : b.keys.iterator().next();
    }
}
// Time: O(1) per operation, Space: O(n)
```

#### 460. [LFU Cache](https://leetcode.com/problems/lfu-cache/) [H]

Description: Design a cache with O(1) `get`/`put` and least-frequently-used eviction, breaking ties by least-recently-used.

Idea: Three maps plus a `minFreq` pointer. `keyToVal` and `keyToFreq` hold the entries; `freqToKeys` maps each frequency to the keys at that frequency, **in insertion order**, so the tie-break is free. Every access bumps a key's frequency, and `minFreq` only ever needs to increase by one — when the bucket it points at empties during a touch, the key that emptied it just moved to `minFreq + 1`.

**Java note.** Python uses `OrderedDict` with `popitem(last=False)` for the per-frequency LRU order. Java's equivalent is `LinkedHashSet`, whose `iterator().next()` gives the oldest inserted key; re-inserting an existing element does *not* refresh its position, which is exactly the behaviour needed here since every touch removes the key from one bucket and adds it to another.

```java
class LFUCache {
    private final int cap;
    private int minFreq;
    private final Map<Integer, Integer> keyToVal = new HashMap<>();
    private final Map<Integer, Integer> keyToFreq = new HashMap<>();
    private final Map<Integer, LinkedHashSet<Integer>> freqToKeys = new HashMap<>();

    public LFUCache(int capacity) { this.cap = capacity; }

    /** Move a key from freq f to f + 1, maintaining minFreq. */
    private void touch(int key) {
        int freq = keyToFreq.get(key);
        LinkedHashSet<Integer> bucket = freqToKeys.get(freq);
        bucket.remove(key);
        if (bucket.isEmpty()) {
            freqToKeys.remove(freq);
            if (minFreq == freq) minFreq++;         // the emptying key went to freq + 1
        }
        keyToFreq.put(key, freq + 1);
        freqToKeys.computeIfAbsent(freq + 1, k -> new LinkedHashSet<>()).add(key);
    }

    public int get(int key) {
        if (!keyToVal.containsKey(key)) return -1;
        touch(key);
        return keyToVal.get(key);
    }

    public void put(int key, int value) {
        if (cap == 0) return;

        if (keyToVal.containsKey(key)) {
            keyToVal.put(key, value);
            touch(key);
            return;
        }

        if (keyToVal.size() == cap) {
            LinkedHashSet<Integer> bucket = freqToKeys.get(minFreq);
            int evict = bucket.iterator().next();   // oldest key at the lowest frequency
            bucket.remove(evict);
            if (bucket.isEmpty()) freqToKeys.remove(minFreq);
            keyToVal.remove(evict);
            keyToFreq.remove(evict);
        }

        keyToVal.put(key, value);
        keyToFreq.put(key, 1);
        freqToKeys.computeIfAbsent(1, k -> new LinkedHashSet<>()).add(key);
        minFreq = 1;                                 // the new key is the least frequent
    }
}
// Time: O(1) per operation, Space: O(capacity)
```

#### 716. [Max Stack](https://leetcode.com/problems/max-stack/) [H]

Description: A stack supporting `push`, `pop`, `top`, `peekMax`, and `popMax`.

Idea: A doubly-linked list gives stack order with O(1) removal from the middle — which `popMax` needs, since the maximum can sit anywhere. A `TreeMap<value, list of nodes>` gives the maximum in O(log n), and the list's **last** node is the most recently pushed copy of that value, which is the one `popMax` must remove.

**Java note.** The Python solution uses a heap with lazy deletion and an `alive` flag: `popMax` is amortized O(log n) but a pathological sequence can leave the heap arbitrarily large with dead entries. Java's `TreeMap` supports exact removal, so this version is worst-case O(log n) with no garbage — a genuinely better structure, not a transliteration.

```java
class MaxStack {
    private static final class Node {
        final int val;
        Node prev, next;

        Node(int val) { this.val = val; }
    }

    private final Node head = new Node(0);          // sentinel: bottom of the stack
    private final Node tail = new Node(0);          // sentinel: top of the stack
    private final TreeMap<Integer, List<Node>> byValue = new TreeMap<>();

    public MaxStack() {
        head.next = tail;
        tail.prev = head;
    }

    private void appendToTop(Node node) {
        Node last = tail.prev;
        last.next = node;
        node.prev = last;
        node.next = tail;
        tail.prev = node;
    }

    private void detach(Node node) {
        node.prev.next = node.next;
        node.next.prev = node.prev;
    }

    public void push(int x) {
        Node node = new Node(x);
        appendToTop(node);
        byValue.computeIfAbsent(x, k -> new ArrayList<>()).add(node);
    }

    public int pop() {
        Node node = tail.prev;
        detach(node);
        removeFromIndex(node);
        return node.val;
    }

    public int top() { return tail.prev.val; }

    public int peekMax() { return byValue.lastKey(); }

    public int popMax() {
        int max = byValue.lastKey();
        List<Node> nodes = byValue.get(max);
        Node node = nodes.remove(nodes.size() - 1);  // most recently pushed copy
        if (nodes.isEmpty()) byValue.remove(max);
        detach(node);
        return max;
    }

    private void removeFromIndex(Node node) {
        List<Node> nodes = byValue.get(node.val);
        nodes.remove(nodes.size() - 1);              // the popped node is the newest of its value
        if (nodes.isEmpty()) byValue.remove(node.val);
    }
}
// Time: push/pop/peekMax/popMax O(log n), top O(1), Space: O(n)
```

#### 146. [LRU Cache](https://leetcode.com/problems/lru-cache/) [M]

Description: Design a cache with O(1) `get` and `put`, evicting the least-recently-used key when full.

Idea: Hash map `key -> node` plus a doubly-linked list ordered by recency. The map gives O(1) lookup, the list gives O(1) reordering, and sentinel head/tail nodes remove every null check from the splice logic.

**Java note.** Java also ships this: `LinkedHashMap` with `accessOrder = true` plus an overridden `removeEldestEntry` is a five-line LRU (see `26U/0.nc150-java.md#lc-0146`). Interviewers usually want the hand-rolled version, so that is what is written here — but knowing the built-in exists is worth a sentence.

```java
class LRUCache {
    private static final class Node {
        int key, val;
        Node prev, next;

        Node(int key, int val) { this.key = key; this.val = val; }
    }

    private final int cap;
    private final Map<Integer, Node> cache = new HashMap<>();
    private final Node head = new Node(0, 0);       // most-recent side
    private final Node tail = new Node(0, 0);       // least-recent side

    public LRUCache(int capacity) {
        this.cap = capacity;
        head.next = tail;
        tail.prev = head;
    }

    private void remove(Node node) {
        node.prev.next = node.next;
        node.next.prev = node.prev;
    }

    private void addFront(Node node) {
        node.prev = head;
        node.next = head.next;
        head.next.prev = node;
        head.next = node;
    }

    public int get(int key) {
        Node node = cache.get(key);
        if (node == null) return -1;
        remove(node);
        addFront(node);
        return node.val;
    }

    public void put(int key, int value) {
        Node node = cache.get(key);
        if (node != null) {
            node.val = value;
            remove(node);
            addFront(node);
            return;
        }

        node = new Node(key, value);
        cache.put(key, node);
        addFront(node);

        if (cache.size() > cap) {
            Node lru = tail.prev;
            remove(lru);
            cache.remove(lru.key);                  // node stores its key precisely for this
        }
    }
}
// Time: O(1) per operation, Space: O(capacity)
```

⚠️ The node must store its `key`, not just its value. Eviction finds the node from the *list* and then needs to delete it from the *map* — without the key that lookup is impossible.

#### 208. [Implement Trie (Prefix Tree)](https://leetcode.com/problems/implement-trie-prefix-tree/) [M]

Description: Implement a trie supporting insert, search, and prefix queries.

Idea: Each node holds 26 child slots and an `end` flag marking a complete word. `search` and `startsWith` differ only in whether they check `end`.

**Java note.** Python uses a `dict` per node. Java's fixed `TrieNode[26]` array is faster and allocation-free per lookup, since the alphabet is known and small. Use a `HashMap<Character, TrieNode>` only when the alphabet is large or unknown (Unicode, arbitrary bytes).

```java
class Trie {
    private static final class TrieNode {
        final TrieNode[] children = new TrieNode[26];
        boolean end;
    }

    private final TrieNode root = new TrieNode();

    public Trie() {}

    public void insert(String word) {
        TrieNode node = root;
        for (char ch : word.toCharArray()) {
            int i = ch - 'a';
            if (node.children[i] == null) node.children[i] = new TrieNode();
            node = node.children[i];
        }
        node.end = true;
    }

    public boolean search(String word) {
        TrieNode node = walk(word);
        return node != null && node.end;
    }

    public boolean startsWith(String prefix) {
        return walk(prefix) != null;
    }

    private TrieNode walk(String s) {
        TrieNode node = root;
        for (char ch : s.toCharArray()) {
            node = node.children[ch - 'a'];
            if (node == null) return null;
        }
        return node;
    }
}
// Time: O(L) per operation where L is word length, Space: O(total chars inserted)
```

#### 355. [Design Twitter](https://leetcode.com/problems/design-twitter/) [M]

Description: Design a simplified Twitter with `postTweet`, `getNewsFeed` (10 most recent), `follow`, and `unfollow`.

Idea: Each user keeps an append-only list of `(time, tweetId)`, and a follow set. The feed is "merge k sorted lists, take 10" — seed a max-heap with each followee's newest tweet, then pop and push that user's next-newest.

**Java note.** Python stores negative timestamps so `heapq`'s min-heap behaves like a max-heap, and relies on tuple comparison for ordering. Java uses an explicit comparator on `int[]`, so timestamps stay positive and the intent is visible at the call site.

```java
class Twitter {
    private int time = 0;
    private final Map<Integer, List<int[]>> tweets = new HashMap<>();      // user -> {time, tweetId}
    private final Map<Integer, Set<Integer>> follows = new HashMap<>();

    public Twitter() {}

    public void postTweet(int userId, int tweetId) {
        tweets.computeIfAbsent(userId, k -> new ArrayList<>()).add(new int[]{++time, tweetId});
    }

    public List<Integer> getNewsFeed(int userId) {
        Set<Integer> followed = follows.computeIfAbsent(userId, k -> new HashSet<>());
        followed.add(userId);                        // you always see your own tweets

        // {time, tweetId, ownerId, nextIndex}, newest first
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> b[0] - a[0]);
        for (int uid : followed) {
            List<int[]> tw = tweets.get(uid);
            if (tw == null || tw.isEmpty()) continue;
            int i = tw.size() - 1;
            heap.offer(new int[]{tw.get(i)[0], tw.get(i)[1], uid, i - 1});
        }

        List<Integer> res = new ArrayList<>();
        while (!heap.isEmpty() && res.size() < 10) {
            int[] top = heap.poll();
            res.add(top[1]);
            int i = top[3];
            if (i >= 0) {
                int[] prev = tweets.get(top[2]).get(i);
                heap.offer(new int[]{prev[0], prev[1], top[2], i - 1});
            }
        }
        return res;
    }

    public void follow(int followerId, int followeeId) {
        follows.computeIfAbsent(followerId, k -> new HashSet<>()).add(followeeId);
    }

    public void unfollow(int followerId, int followeeId) {
        if (followerId == followeeId) return;        // cannot unfollow yourself
        Set<Integer> s = follows.get(followerId);
        if (s != null) s.remove(followeeId);
    }
}
// Time: getNewsFeed O((k + 10) log k) for k followees, others O(1), Space: O(users + tweets)
```

#### 380. [Insert Delete GetRandom O(1)](https://leetcode.com/problems/insert-delete-getrandom-o1/) [M]

Description: Design a set supporting O(1) `insert`, `remove`, and `getRandom`.

Idea: An `ArrayList` of values gives O(1) uniform random access; a map `value -> index` gives O(1) lookup. Removal is the trick: swap the target with the **last** element, update that element's index, then remove from the end — deleting from the middle of a list would be O(n).

**Java note.** Python's `random.choice(list)` becomes `list.get(random.nextInt(list.size()))`.

```java
class RandomizedSet {
    private final List<Integer> vals = new ArrayList<>();
    private final Map<Integer, Integer> index = new HashMap<>();
    private final Random random = new Random();

    public RandomizedSet() {}

    public boolean insert(int val) {
        if (index.containsKey(val)) return false;
        index.put(val, vals.size());
        vals.add(val);
        return true;
    }

    public boolean remove(int val) {
        Integer i = index.get(val);
        if (i == null) return false;

        int last = vals.get(vals.size() - 1);
        vals.set(i, last);                           // move the tail into the hole
        index.put(last, i);
        vals.remove(vals.size() - 1);                // O(1): removing from the end
        index.remove(val);
        return true;
    }

    public int getRandom() {
        return vals.get(random.nextInt(vals.size()));
    }
}
// Time: O(1) per operation, Space: O(n)
```

⚠️ Order matters when removing the *last* element: `index.put(last, i)` runs before `index.remove(val)`, so when `val == last` the stale entry is cleaned up rather than resurrected.

#### 622. [Design Circular Queue](https://leetcode.com/problems/design-circular-queue/) [M]

Description: Implement a fixed-size circular queue.

Idea: A fixed array plus a head index and a live count. Storing the **count** rather than a tail index is what makes full and empty distinguishable — with two indices alone, `head == tail` is ambiguous.

```java
class MyCircularQueue {
    private final int k;
    private final int[] q;
    private int head;
    private int count;

    public MyCircularQueue(int k) {
        this.k = k;
        this.q = new int[k];
    }

    public boolean enQueue(int value) {
        if (isFull()) return false;
        q[(head + count) % k] = value;
        count++;
        return true;
    }

    public boolean deQueue() {
        if (isEmpty()) return false;
        head = (head + 1) % k;
        count--;
        return true;
    }

    public int Front() { return isEmpty() ? -1 : q[head]; }

    public int Rear() { return isEmpty() ? -1 : q[(head + count - 1) % k]; }

    public boolean isEmpty() { return count == 0; }

    public boolean isFull() { return count == k; }
}
// Time: O(1) per operation, Space: O(k)
```

#### 895. [Maximum Frequency Stack](https://leetcode.com/problems/max-frequency-stack/) [M]

Description: Design a stack that always pops the element with the highest frequency, breaking ties by the most recently pushed.

Idea: Track `val -> freq` and `freq -> stack of vals`, plus a running `maxFreq`. Pushing a value onto the stack for *its new frequency* means each frequency level keeps its own recency order, so the tie-break falls out for free. Popping takes from the `maxFreq` stack and decrements `maxFreq` when that level empties.

The non-obvious part: a value is left in *every* lower-frequency stack it passed through, and that is correct — after popping one copy, the remaining copies are exactly what the lower levels hold.

```java
class FreqStack {
    private final Map<Integer, Integer> freq = new HashMap<>();
    private final Map<Integer, Deque<Integer>> group = new HashMap<>();
    private int maxFreq;

    public FreqStack() {}

    public void push(int val) {
        int f = freq.merge(val, 1, Integer::sum);
        maxFreq = Math.max(maxFreq, f);
        group.computeIfAbsent(f, k -> new ArrayDeque<>()).push(val);
    }

    public int pop() {
        Deque<Integer> top = group.get(maxFreq);
        int val = top.pop();
        freq.merge(val, -1, Integer::sum);
        if (top.isEmpty()) maxFreq--;
        return val;
    }
}
// Time: O(1) per operation, Space: O(n)
```

#### 981. [Time Based Key-Value Store](https://leetcode.com/problems/time-based-key-value-store/) [M]

Description: A key-value store where each key holds timestamped values; `get` returns the value at the largest timestamp `<=` the query.

Idea: One sorted map per key. "Largest key at or below x" is precisely `TreeMap.floorEntry`.

**Java note.** This one does not translate. The Python solution binary-searches a list of tuples with `bisect_right(arr, (timestamp, chr(127)))` — a hack that fabricates a sentinel string guaranteed to sort after any real value, exploiting lexicographic tuple comparison. Java has no tuple ordering and no such sentinel, so the natural Java solution is a different structure entirely: `TreeMap.floorEntry` says what the code means, in one call.

```java
class TimeMap {
    private final Map<String, TreeMap<Integer, String>> store = new HashMap<>();

    public TimeMap() {}

    public void set(String key, String value, int timestamp) {
        store.computeIfAbsent(key, k -> new TreeMap<>()).put(timestamp, value);
    }

    public String get(String key, int timestamp) {
        TreeMap<Integer, String> tm = store.get(key);
        if (tm == null) return "";
        Map.Entry<Integer, String> e = tm.floorEntry(timestamp);   // largest key <= timestamp
        return e == null ? "" : e.getValue();
    }
}
// Time: set O(log n), get O(log n), Space: O(n)
```

Alternative when the problem guarantees strictly increasing timestamps (as LeetCode does): keep a plain `ArrayList` per key and hand-roll the binary search, giving O(1) `set`. That version is in `26U/0.nc150-java.md#lc-0981`.

#### 1146. [Snapshot Array](https://leetcode.com/problems/snapshot-array/) [M]

Description: An array supporting O(1) snapshots and historical value queries.

Idea: Do not copy the array on `snap` — that would be O(length) per snapshot. Instead each index keeps its own history of `(snapId, value)` records, and `snap` just increments a counter. A query binary-searches that index's history for the newest record at or before the requested snapshot.

**Java note.** Same problem as 981: Python's `bisect_right(arr, (snap_id, float('inf')))` relies on tuple ordering with an infinite sentinel. Rewritten with a per-index `TreeMap` and `floorEntry`.

```java
class SnapshotArray {
    private final TreeMap<Integer, Integer>[] history;
    private int snapId;

    @SuppressWarnings("unchecked")
    public SnapshotArray(int length) {
        history = new TreeMap[length];
        for (int i = 0; i < length; i++) {
            history[i] = new TreeMap<>();
            history[i].put(0, 0);                    // every index starts at 0
        }
    }

    public void set(int index, int val) {
        history[index].put(snapId, val);             // overwrites within the same snapshot
    }

    public int snap() {
        return snapId++;                             // O(1): no copying
    }

    public int get(int index, int snapId) {
        return history[index].floorEntry(snapId).getValue();
    }
}
// Time: set/get O(log S), snap O(1), Space: O(length + total sets)
```

#### 1472. [Design Browser History](https://leetcode.com/problems/design-browser-history/) [M]

Description: Implement browser history with `visit`, `back`, and `forward`.

Idea: Two stacks. `back` moves the current page onto the forward stack; `visit` clears the forward stack, because navigating somewhere new discards the branch you could have gone forward into. Keeping the current page on top of `backStack` (rather than in its own field) is what makes `back(steps)` a simple loop with the `size() > 1` guard.

```java
class BrowserHistory {
    private final Deque<String> backStack = new ArrayDeque<>();
    private final Deque<String> forwardStack = new ArrayDeque<>();

    public BrowserHistory(String homepage) {
        backStack.push(homepage);
    }

    public void visit(String url) {
        backStack.push(url);
        forwardStack.clear();                        // the forward branch is now unreachable
    }

    public String back(int steps) {
        while (steps > 0 && backStack.size() > 1) {  // never pop past the homepage
            forwardStack.push(backStack.pop());
            steps--;
        }
        return backStack.peek();
    }

    public String forward(int steps) {
        while (steps > 0 && !forwardStack.isEmpty()) {
            backStack.push(forwardStack.pop());
            steps--;
        }
        return backStack.peek();
    }
}
// Time: back/forward O(steps), visit O(1) amortized, Space: O(n)
```

Alternative: an `ArrayList` plus a current-index pointer, where `visit` truncates everything after the index. Same complexity, and `forward` becomes O(1); worth mentioning as the follow-up.

#### 155. [Min Stack](https://leetcode.com/problems/min-stack/) [E]

Description: Design a stack supporting `push`, `pop`, `top`, and retrieving the minimum element in O(1).

##### Approach 1: Parallel min-stack

Idea: Keep a second stack whose top is always the minimum of everything currently in the main stack. Pushing the running minimum at every level makes `pop` a plain pop on both.

```java
class MinStack {
    private final Deque<Integer> st = new ArrayDeque<>();
    private final Deque<Integer> minSt = new ArrayDeque<>();

    public MinStack() {}

    public void push(int val) {
        st.push(val);
        minSt.push(minSt.isEmpty() ? val : Math.min(val, minSt.peek()));
    }

    public void pop() {
        st.pop();
        minSt.pop();
    }

    public int top() { return st.peek(); }

    public int getMin() { return minSt.peek(); }
}
// Time: O(1) per operation, Space: O(n)
```

##### Approach 2: Single stack of deltas

Idea: Store `val - min` instead of `val`. A negative entry means this push lowered the minimum, so popping it recovers the previous minimum as `min - delta`.

**Java note.** `val - min` can exceed `int` range when values straddle `Integer.MIN_VALUE`/`MAX_VALUE`, so the deltas are stored as `long`. Python's unbounded integers hide this; Java does not.

```java
class MinStack {
    private final Deque<Long> stack = new ArrayDeque<>();
    private long min;

    public MinStack() {}

    public void push(int val) {
        if (stack.isEmpty()) {
            stack.push(0L);
            min = val;
        } else {
            stack.push(val - min);                   // long arithmetic: cannot overflow
            if (val < min) min = val;
        }
    }

    public void pop() {
        long popped = stack.pop();
        if (popped < 0) min = min - popped;          // this push had set the minimum
    }

    public int top() {
        long t = stack.peek();
        return (int) (t > 0 ? t + min : min);
    }

    public int getMin() { return (int) min; }
}
// Time: O(1) per operation, Space: O(n)
```

#### 225. [Implement Stack using Queues](https://leetcode.com/problems/implement-stack-using-queues/) [E]

Description: Implement a LIFO stack using only queue operations.

##### Approach 1: One queue, rotate on push

Idea: After enqueuing the new element, rotate every *previous* element to the back. The queue front is then always the most recently pushed element, so `pop` and `top` are O(1).

```java
class MyStack {
    private final Queue<Integer> q = new ArrayDeque<>();

    public MyStack() {}

    public void push(int x) {
        q.offer(x);
        for (int i = q.size() - 1; i > 0; i--) {     // rotate the older elements behind x
            q.offer(q.poll());
        }
    }

    public int pop() { return q.poll(); }

    public int top() { return q.peek(); }

    public boolean empty() { return q.isEmpty(); }
}
// Time: push O(n), others O(1), Space: O(n)
```

##### Approach 2: Two queues, work on pop

Idea: Push is O(1). On pop, move all but the last element to the second queue, take the survivor, then swap the roles of the two queues.

**Java note.** Python swaps queues with tuple assignment `self.q1, self.q2 = self.q2, self.q1`. Java needs an explicit temporary — or, as below, non-final fields and a three-line swap.

```java
class MyStack {
    private Queue<Integer> q1 = new ArrayDeque<>();
    private Queue<Integer> q2 = new ArrayDeque<>();

    public MyStack() {}

    public void push(int x) { q1.offer(x); }

    public int pop() {
        while (q1.size() > 1) q2.offer(q1.poll());
        int val = q1.poll();
        Queue<Integer> tmp = q1;                     // no tuple assignment in Java
        q1 = q2;
        q2 = tmp;
        return val;
    }

    public int top() {
        int val = pop();
        q1.offer(val);                               // q1 is now empty-ish; re-push is safe
        return val;
    }

    public boolean empty() { return q1.isEmpty(); }
}
// Time: pop/top O(n), push O(1), Space: O(n)
```

#### 232. [Implement Queue using Stacks](https://leetcode.com/problems/implement-queue-using-stacks/) [E]

Description: Implement a FIFO queue using only two stacks.

Idea: Lazy transfer. Push onto `inStack`; on `pop`/`peek`, dump `inStack` into `outStack` (which reverses the order) **only when `outStack` is empty**. Every element is moved at most once, so each operation is amortized O(1) even though a single `pop` can be O(n).

```java
class MyQueue {
    private final Deque<Integer> inStack = new ArrayDeque<>();
    private final Deque<Integer> outStack = new ArrayDeque<>();

    public MyQueue() {}

    public void push(int x) { inStack.push(x); }

    /** Refill only when out is empty — refilling early would break the ordering. */
    private void transfer() {
        if (outStack.isEmpty()) {
            while (!inStack.isEmpty()) outStack.push(inStack.pop());
        }
    }

    public int pop() {
        transfer();
        return outStack.pop();
    }

    public int peek() {
        transfer();
        return outStack.peek();
    }

    public boolean empty() { return inStack.isEmpty() && outStack.isEmpty(); }
}
// Time: amortized O(1) per operation, Space: O(n)
```
