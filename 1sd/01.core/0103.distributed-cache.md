# Design a Distributed Cache

Design a multi-node cache that serves low-latency reads, scales horizontally, and remains operable during node failure and topology changes.

## Scope decisions to make

- Cache-aside service versus a transparent cache tier.
- String/blob key-value API versus richer data structures.
- Single region first; multi-region replication is an extension.
- Decide whether availability or strict read-after-write behavior wins during failure.

## Non-functionals to pin down

- Peak GET/SET QPS and read/write ratio.
- p99 latency and availability target.
- Key/value size distribution, TTL range, and hot-set size.
- Acceptable stale-read and eviction behavior.

## The estimation that decides something

Estimate the resident hot set plus metadata and replication overhead. Use peak per-node QPS and skew—not average cluster QPS—to choose node count and headroom.

## Skeleton diagram

```text
Client library -> routing ring/config -> cache node shard
                     |                    |-> memory + eviction
                     |                    `-> replication/failover
                     `-> membership/control plane
```

## The hard part

Define consistent-hash ownership, virtual nodes, replication, membership changes, and what happens to in-flight reads/writes when a node disappears. Address hot keys separately from uniform distribution.

## Tradeoffs to defend

- Client-side routing versus proxy routing.
- LRU/LFU/TTL eviction and workload sensitivity.
- Replication versus usable memory and write amplification.
- Availability during failover versus stale or lost cache writes.

## Top failure mode

A node loss remaps too many keys, drops hit rate, and creates a database stampede. Cover bounded remapping, request coalescing, admission control, warm-up, and origin protection.

## Pushback ladder

1. How does consistent hashing reduce movement, and what does it not solve?
2. One key receives 20% of traffic; adding nodes does not help. What changes?
3. The cache becomes the system of record. Which assumptions and mechanisms must be replaced?
