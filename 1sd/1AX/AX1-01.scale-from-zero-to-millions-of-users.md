# Volume 1, Chapter 1: Scale From Zero To Millions Of Users

This is a concept progression, not a standalone design prompt. Use it to learn which workload change justifies each layer; do not reproduce the progression mechanically in every interview.

## Progression and decision trigger

| Stage | Add only when | Mechanism bought | Cost introduced |
| --- | --- | --- | --- |
| One app + one SQL database | Initial load fits one failure domain | Simple transactions and operations | Coupled scaling, single failure domain |
| Separate app and database | CPU/memory scale independently | Independent capacity and deployment | Network dependency and more failure paths |
| Load balancer + app fleet | Stateless request load exceeds one host | Horizontal compute and failover | Health checks, draining, config convergence |
| Read replicas | Read QPS or isolation requires them | Read scaling and failover candidate | Replication lag and stale reads |
| Cache | Hot reads violate latency/DB budget | Lower latency and origin load | Invalidation, stampede, stale data |
| CDN | Static/media egress and distance dominate | Edge locality and origin protection | Purge complexity and cache-key correctness |
| Queue/workers | Slow side effects block requests or burst | Temporal decoupling and buffering | Lag, duplicates, ordering, replay ownership |
| Sharding | State/write throughput exceeds one primary | Horizontal state capacity | Cross-shard work, skew, rebalancing |
| Multi-region | Latency, residency, or DR justifies it | Regional isolation/locality | Conflict, failover, cost, operational complexity |

## Mechanism checkpoints

- **Statelessness:** name which state moved out of the process; local memory still exists and can still couple requests.
- **Replication:** state sync/async mode, read policy, failover authority, and user-visible lag.
- **Caching:** define key, value, TTL/invalidation, miss behavior, and stampede protection.
- **Partitioning:** define shard key, skew strategy, routing, and online movement.
- **Asynchrony:** define delivery semantics, ordering scope, idempotency, backpressure, and reconciliation.

## Defeater

“More scalable” is not automatically “better.” If measured load fits one well-operated relational database and stateless service, extra distributed components lower reliability by adding coordination and failure modes.

## Recall card

Explain the path from one server to a partitioned multi-region system in 90 seconds. For every added layer, name the measured trigger and one new failure mode.
