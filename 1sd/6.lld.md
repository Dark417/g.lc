## 0. One-Minute Version

- LLD rounds test whether you can turn a bounded problem into **clean classes, interfaces and working code**
- Approach: clarify use cases → entities → relationships → interfaces → key methods → patterns → concurrency → extensibility
- Interviewers look for: single responsibility, programming to interfaces, the right pattern (not every pattern), thread safety where it matters, and how a new requirement fits without rewrites
- Where it shows up: Microsoft (often), Amazon (sometimes), Oracle Health / some OCI teams, machine-coding rounds at startups
- 🗣 "I'll pin down the use cases, sketch the core classes and interfaces, then code the critical path and show how a new type plugs in without changing existing code."

## 3. OO Fundamentals ★★★

- **Encapsulation**: hide state; expose behavior (`ticket.close()` instead of setting fields)
- **Abstraction**: interfaces describe what, not how
- **Inheritance vs composition**: prefer composition; inherit only for true "is-a" with shared behavior
- **Polymorphism**: callers depend on the interface; implementations vary
- Java 17 tools
  - `interface` with default methods
  - `record` for immutable value objects (`record Money(long cents, String currency)`)
  - `enum` with behavior for fixed sets (`VehicleType`, `State`)
  - `sealed` interfaces to restrict implementations (`sealed interface Shape permits Circle, Square`)
- Interface vs abstract class
  - Interface: a capability, multiple implementations, no state
  - Abstract class: shared state / code among closely related classes

<a id="s4"></a>
## 4. SOLID ★★★

| Principle | Plain idea | Smell it prevents |
|---|---|---|
| S — Single responsibility | One reason to change per class | God classes (`ParkingLotManager` doing everything) |
| O — Open/closed | Add behavior by adding classes, not editing old ones | Growing `switch` on type |
| L — Liskov substitution | Subtypes work wherever the parent is expected | `Square extends Rectangle` breaking setters |
| I — Interface segregation | Small, focused interfaces | Implementations throwing `UnsupportedOperationException` |
| D — Dependency inversion | Depend on abstractions; inject implementations | Hard-coded `new MySqlRepository()` inside logic |

```java
// Open/closed + dependency inversion: new pricing = new class, no edits elsewhere
interface PricingStrategy { Money price(Duration parked, VehicleType type); }

final class HourlyPricing implements PricingStrategy {
    public Money price(Duration parked, VehicleType type) {
        long hours = Math.max(1, (parked.toMinutes() + 59) / 60);
        return new Money(hours * type.hourlyRateCents(), "USD");
    }
}

final class ExitGate {
    private final PricingStrategy pricing;            // injected
    ExitGate(PricingStrategy pricing) { this.pricing = pricing; }
    Money charge(Ticket t, Instant now) {
        return pricing.price(Duration.between(t.entryTime(), now), t.vehicleType());
    }
}
```

<a id="s5"></a>
## 5. Design Patterns That Actually Show Up ★★★

| Pattern | Solves | Typical LLD use |
|---|---|---|
| Strategy | Swap algorithms at runtime | Pricing, slot assignment, eviction policy, rate-limit algorithm |
| Factory / factory method | Create objects without exposing concrete classes | Vehicle / payment / notification creation |
| Builder | Construct complex objects step by step | Requests, configs, immutable entities with many fields |
| Singleton | One instance | Config, registry — use sparingly; prefer DI |
| Observer / pub-sub | Notify many listeners of events | Display boards, notifications, event bus |
| State | Behavior depends on state, with transitions | Vending machine, elevator, order / booking lifecycle |
| Command | Encapsulate a request as an object | Elevator requests, undo / redo, job queues |
| Chain of responsibility | Pass a request along handlers | Middleware, validation, ATM cash dispenser |
| Decorator | Add behavior by wrapping | Logging / metrics around a service, pizza toppings |
| Adapter | Make an incompatible interface fit | Third-party payment gateways |
| Facade | Simple entry point over subsystems | `BookingService` over inventory + payment + notification |
| Template method | Fixed algorithm skeleton, steps overridden | Report generation, parsers |
| Iterator | Traverse without exposing internals | Custom collections |

- Rule: name a pattern only when it removes a real `if/else` or coupling; don't pattern-stuff
- 🗣 "State pattern for the vending machine: each state class handles insertCoin and select, so invalid transitions are impossible by construction."

<a id="s6"></a>
## 6. Concurrency In LLD ★★★

- Where it comes up: parking spot assignment, seat booking, rate limiters, caches, counters, job queues
- Tools (Java)

| Tool | Use |
|---|---|
| `synchronized` | Simple mutual exclusion on one object |
| `ReentrantLock` | Try-lock, timeouts, fairness |
| `ReadWriteLock` | Many readers, few writers |
| `AtomicLong` / `AtomicReference` | Lock-free counters, CAS updates |
| `ConcurrentHashMap` (`compute`, `merge`) | Thread-safe maps with atomic per-key updates |
| `BlockingQueue` | Producer-consumer |
| `ExecutorService` | Thread pools |
| Immutability (records) | Share safely without locks |

- Rules
  - Keep critical sections small
  - Lock ordering to avoid deadlock
  - Prefer per-key locking (or `ConcurrentHashMap.compute`) over one global lock
  - Check-then-act must be atomic (`putIfAbsent`, CAS, or inside the lock)
- 🗣 "Seat holds use ConcurrentHashMap.compute per seat, so two threads can't both claim it."

<a id="s9-1"></a>
### 9.1 LRU Cache (Thread-Safe)

```java
import java.util.HashMap;
import java.util.Map;
import java.util.concurrent.locks.ReentrantLock;

public final class LruCache<K, V> {
    private final class Node {
        final K key; V value; Node prev, next;
        Node(K key, V value) { this.key = key; this.value = value; }
    }

    private final int capacity;
    private final Map<K, Node> map = new HashMap<>();
    private final Node head = new Node(null, null);   // most recent after head
    private final Node tail = new Node(null, null);   // least recent before tail
    private final ReentrantLock lock = new ReentrantLock();

    public LruCache(int capacity) {
        if (capacity <= 0) throw new IllegalArgumentException("capacity must be > 0");
        this.capacity = capacity;
        head.next = tail; tail.prev = head;
    }

    public V get(K key) {
        lock.lock();
        try {
            Node n = map.get(key);
            if (n == null) return null;
            moveToFront(n);
            return n.value;
        } finally { lock.unlock(); }
    }

    public void put(K key, V value) {
        lock.lock();
        try {
            Node n = map.get(key);
            if (n != null) { n.value = value; moveToFront(n); return; }
            if (map.size() == capacity) {
                Node lru = tail.prev;
                unlink(lru);
                map.remove(lru.key);
            }
            Node fresh = new Node(key, value);
            map.put(key, fresh);
            addFront(fresh);
        } finally { lock.unlock(); }
    }

    private void moveToFront(Node n) { unlink(n); addFront(n); }
    private void unlink(Node n) { n.prev.next = n.next; n.next.prev = n.prev; }
    private void addFront(Node n) {
        n.next = head.next; n.prev = head;
        head.next.prev = n; head.next = n;
    }
}
```

- Notes
  - HashMap gives O(1) lookup; the doubly linked list gives O(1) move / evict
  - One lock keeps it simple and correct; for high concurrency, shard into N caches by key hash
  - `LinkedHashMap(accessOrder = true)` + `removeEldestEntry` is the library shortcut — mention it, then show you can build it

### 9.2 Token Bucket Rate Limiter (Per Key)

```java
import java.util.concurrent.ConcurrentHashMap;
import java.util.function.LongSupplier;

public final class TokenBucketLimiter {
    private record Bucket(double tokens, long lastRefillNanos) {}

    private final double capacity;
    private final double refillPerNano;
    private final LongSupplier clock;                 // injectable for tests
    private final ConcurrentHashMap<String, Bucket> buckets = new ConcurrentHashMap<>();

    public TokenBucketLimiter(double capacity, double refillPerSecond, LongSupplier clock) {
        this.capacity = capacity;
        this.refillPerNano = refillPerSecond / 1_000_000_000.0;
        this.clock = clock;
    }

    public boolean tryAcquire(String key) {
        boolean[] allowed = new boolean[1];
        buckets.compute(key, (k, b) -> {
            long now = clock.getAsLong();
            double tokens = (b == null) ? capacity
                    : Math.min(capacity, b.tokens() + (now - b.lastRefillNanos()) * refillPerNano);
            if (tokens >= 1.0) { allowed[0] = true; tokens -= 1.0; }
            return new Bucket(tokens, now);
        });
        return allowed[0];
    }
}
```

- Notes
  - `compute` makes refill + take atomic per key without a global lock
  - Clock is injected so tests can control time
  - Strategy hook: put `tryAcquire` behind a `RateLimiter` interface to swap in sliding window
  - Memory: evict idle buckets (e.g. scheduled cleanup) in a real system; distributed version uses Redis + Lua (1qs.md 0.6)

<a id="s10"></a>
## 10. Machine-Coding Tips ★★

- Package by concept: `model`, `service`, `strategy`, `repository`
- Interfaces first, then one implementation each
- In-memory repositories behind interfaces (swap for a DB later)
- A small `main` or unit tests that run the core flow
- Validate inputs; use enums for fixed sets; immutable value objects
- Leave time to demonstrate one extension (new vehicle type, new pricing)

<a id="s11"></a>
## 11. Common Mistakes ★★

- Jumping into code before agreeing on use cases
- God class that holds all logic
- Inheritance trees for things that vary by data (use enums / strategies)
- Public mutable fields; setters everywhere
- Ignoring concurrency where shared state obviously exists
- Pattern-stuffing to look sophisticated
- No demonstration of extensibility
