# 03db.03s3.05conditional-writes Conditional Writes

> How `If-None-Match: *` makes a PUT create-only, and how to read its 412 and 409 answers.

## 1. Mechanism

`If-None-Match: *` on PutObject (and CompleteMultipartUpload) writes only if the key does not exist (Amazon Web Services (AWS), 2024-08).

→ First writer returns 200  
→ Loser gets 412 PreconditionFailed  
→ Concurrent in-flight writers may get 409 ConditionalRequestConflict: retry

- 412 = "already exists", not an error
- 409 = retry with backoff
- Before Aug 2024 this needed DynamoDB or head-then-put (racy)

## 2. Uses and Limits

Create-only writes give Simple Storage Service (S3) a primitive for locks and exactly-once landing.

- Uses
  - Leader lock files
  - Idempotent "create once"
  - Exactly-once landing of a batch
  - Leader election with only S3 (no DynamoDB)
- Limits
  - Create-only
    - `If-Match` (compare Entity Tag (ETag)) is a separate conditional for updates
  - On a versioned bucket, "exists" means a current non-delete-marker version
  - No Time To Live (TTL) / fencing
    - A crashed lock holder needs an external expiry

## 3. Code

The adapter maps 412 to `created=false`; the Representational State Transfer (REST) layer maps that to Hypertext Transfer Protocol (HTTP) 409.

**Java**

```java
// infra/_03db_03s3/S3LakeStore.java
@Override
public CreateResult putIfAbsent(String key, byte[] body) {
    try {
        PutObjectResponse r = s3.putObject(PutObjectRequest.builder()
                .bucket(bucket).key(key).ifNoneMatch("*").build(), RequestBody.fromBytes(body));
        return new CreateResult(true, r.eTag(), r.versionId());
    } catch (S3Exception e) {
        if (e.statusCode() == 412) { // PreconditionFailed: key already exists, nothing written
            return new CreateResult(false, null, null);
        }
        throw e; // 409 and others: let the caller / SDK retry policy decide
    }
}
```

```java
// api/_03db_03s3/S3Controller.java
// Create-only: 201 when created, 409 when the key already exists.
@PutMapping("/create-only")
public ResponseEntity<CreateResult> createOnly(@RequestParam String key, @RequestBody byte[] body) {
    CreateResult r = store.putIfAbsent(key, body);
    return ResponseEntity.status(r.created() ? HttpStatus.CREATED : HttpStatus.CONFLICT).body(r);
}
```

**Python**

```python
# app/infra/_03db_03s3.py
def put_if_absent(key: str, body: bytes) -> CreateResult:
    try:
        r = _s3().put_object(Bucket=_bucket(), Key=key, Body=body, IfNoneMatch="*")
    except ClientError as e:
        status = e.response["ResponseMetadata"]["HTTPStatusCode"]
        if status == 412:  # PreconditionFailed: key exists, nothing written
            return CreateResult(created=False)
        raise  # 409 and others: caller decides
    return CreateResult(created=True, etag=r.get("ETag"), version_id=r.get("VersionId"))
```

**Catch**

- Do not treat 412 as a failure; it is the expected "lost the race" answer
- Do not swallow 409; it needs a retry

## 4. Manifest Commit Pattern

S3 has no multi-object atomicity, so many writers publish through one conditional commit.

→ Each writer writes files under a unique run prefix  
→ One manifest / table-format commit is published with a conditional write  
→ Readers read only the manifest  
⇒ Readers never see half-written data  
→ Compaction and vacuum clean old files

```text
// illustrative
runs/<run-id>/part-0001.parquet ... part-0420.parquet
_manifests/v00042.json   ← PUT If-None-Match: *  (only one writer wins v42)
```
