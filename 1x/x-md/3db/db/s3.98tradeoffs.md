## 1. When to Use / Not

S3 fits write-once, read-many blobs; it is wrong for file-system or low-latency small-item access.

- Use
  - Blobs and files from kilobytes (KB) to terabytes (TB), written once, read many
  - Data lake storage for Athena / Redshift / Firehose
  - Direct client uploads through presigned Uniform Resource Locators (URLs)
  - Backups, exports, build artifacts
- Do not use
  - Low-latency random reads of tiny items
    - S3 first-byte latency is order of tens of milliseconds (ms)
    - Use DynamoDB
  - Portable Operating System Interface (POSIX) semantics: append, rename, locking
    - Use Elastic File System (EFS)
  - Block device for a database
    - Use Elastic Block Store (EBS)
  - Frequent in-place small updates to one object
    - Each update rewrites the whole object

## 2. Knobs and Best Practices

Each rule is paired with the failure it prevents.

### 2.1 Bucket Settings

- Block Public Access on (Terraform does)
  - Prevents accidental public buckets
- Access Control Lists (ACLs) off (`BucketOwnerEnforced`)
  - Gives one permission model: Identity and Access Management (IAM) + bucket policy
- Default encryption Server-Side Encryption with Key Management Service keys (SSE-KMS) + Bucket Key
  - Gives Key Management Service (KMS) audit without per-request KMS cost explosion
  - See [06 Encryption](03s3.06encryption.md)
- Abort-incomplete-multipart lifecycle
  - Stops invisible part billing
- Noncurrent-version expiry
  - Stops versioning cost growth
  - See [07 Versioning](03s3.07versioning-lifecycle.md)

### 2.2 Client Practices

- Spread hot writes across prefixes (hash or date prefix)
  - Avoids per-prefix throttling
- Retry 503 SlowDown with exponential backoff and jitter
  - Software Development Kit (SDK) does this by default
- Parallel ranged GETs for big downloads
  - Gives throughput beyond one connection
- Use Transfer Manager / `upload_file` for files
  - Gives automatic multipart, parallelism, abort on failure
  - See [03 Multipart](03s3.03multipart-transfer.md)
- Presign with the shortest useful expiry
  - Gives a smaller leak window
- Store the S3 key (not a presigned URL) in your database
  - Reason: URLs expire

## 3. Comparison

S3 holds bytes; the siblings win only when a file system, block device, or small-record database is required.

| Option | What it is | Strength | Weakness | Choose when |
|---|---|---|---|---|
| S3 | Regional object store | Cheap per gigabyte (GB), 11-nines durability design, unlimited size, presigned URLs | No append/rename; higher latency than disk | Blobs, lake, backups |
| EFS | Managed Network File System (NFS) file system | POSIX, shared mount, append, locks | Several times the S3 price per GB (order of magnitude), regional throughput modes | Many instances share a real file system |
| EBS | Network block volume | Lowest latency, boots Operating System (OS), database disks | One Availability Zone (AZ), one instance (Multi-Attach limited), pay for provisioned size | Single-host disk, databases |
| DynamoDB | Key-value / document database (DB) | Single-digit ms, conditional updates, indexes | 400 KB item cap; per-request cost for big values | Metadata and small records |

- Pick for blobs
  - S3 holds the bytes
  - DynamoDB or Aurora holds metadata + the S3 key

Pick: S3 for blobs, unless a POSIX shared file system (EFS) or a block device (EBS) is required.

## 4. Failure Modes

Most S3 failures are throttling, signature or KMS permission errors, and silent cost growth.

### 4.1 Requests and Auth

| Failure | Trigger | Detect | Fix |
|---|---|---|---|
| 503 SlowDown | Burst above per-prefix rate on a new prefix | 503 in client metrics, CloudWatch 5xx | Backoff + jitter, spread prefixes, warm up gradually |
| 403 SignatureDoesNotMatch | Presigned PUT sent with different headers | 403 on upload | Send exactly the signed headers (content-type, SSE) |
| Presigned URL dies early | Signed with role/Security Token Service (STS) credentials | Failures before expiry | Sign with longer-lived credentials, or issue URLs just-in-time |
| 403 AccessDenied on KMS | Caller lacks `kms:GenerateDataKey` / `kms:Decrypt` | Error names KMS | Grant KMS use in IAM and key policy |
| Stale reads via Content Delivery Network (CDN) | Cache in front of S3 | Old Entity Tag (ETag) at edge | Versioned key names or cache invalidation |

### 4.2 Writes, Versions, Cost

| Failure | Trigger | Detect | Fix |
|---|---|---|---|
| Orphan multipart parts | Crash between create and complete | `ListMultipartUploads`, storage cost | Abort in `except`; lifecycle abort rule |
| 412 PreconditionFailed | Create-only write on existing key | Status 412 | Treat as "already exists", not an error |
| 409 ConditionalRequestConflict | Concurrent conditional writes | Status 409 | Retry with backoff |
| Surprise 404 after delete | Delete marker is the latest version | `ListObjectVersions` shows marker | Delete the marker to restore the previous version |
| Cost growth | Versions + Infrequent Access (IA) minimum charges + small objects in IA | Cost Explorer, Storage Lens | Noncurrent expiry, compact small files, right class |
