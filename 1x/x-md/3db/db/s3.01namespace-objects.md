## 1. Flat Namespace

S3 stores bucket → key → object; no hierarchy is stored.

- Object = key + bytes + metadata + optional version id
- `a/b/c.txt` is one key, not a file inside two directories
- Consequence
  - "Rename a folder" = copy + delete every key, not O(1)
  - Listing is paginated
    - Max 1,000 keys per response
    - A continuation token drives the next page
  - A 0-byte key ending in `/` is only a console convention
- Prefix is the only index
  - Lake layouts (`dt=...` partitions) exist for this reason
  - Listing cost is per 1,000 keys scanned
  - Deep prefix scans over millions of keys are slow and billed

### 1.1 Listing With Prefix and Delimiter

`ListObjectsV2` with `prefix` + `delimiter=/` turns flat keys into a folder view.

- Keys with the delimiter after the prefix collapse into `CommonPrefixes`
- Those common prefixes are the "folders"
- Keys directly under the prefix come back in `Contents`

**Java**

```java
// infra/_03db_03s3/S3LakeStore.java
@Override
public ListingPage listFolder(String prefix) {
    List<String> keys = new ArrayList<>();
    List<String> folders = new ArrayList<>();
    int pages = 0;
    // Paginator follows the continuation token; one response holds max 1,000 keys.
    for (ListObjectsV2Response page : s3.listObjectsV2Paginator(ListObjectsV2Request.builder()
            .bucket(bucket).prefix(prefix).delimiter("/").maxKeys(1000).build())) {
        pages++;
        page.contents().forEach(o -> keys.add(o.key()));
        page.commonPrefixes().stream().map(CommonPrefix::prefix).forEach(folders::add); // the "folders"
    }
    return new ListingPage(keys, folders, pages);
}
```

**Python**

```python
# app/infra/_03db_03s3.py
def list_folder(prefix: str) -> ListingPage:
    keys: list[str] = []
    folders: list[str] = []
    pages = 0
    paginator = _s3().get_paginator("list_objects_v2")
    for page in paginator.paginate(Bucket=_bucket(), Prefix=prefix, Delimiter="/"):
        pages += 1
        keys.extend(o["Key"] for o in page.get("Contents", []))
        folders.extend(p["Prefix"] for p in page.get("CommonPrefixes", []))  # shared key prefixes
    return ListingPage(keys, folders, pages)
```

**Catch**

- Folders are just key prefixes; no directory object exists
- Skipping the paginator silently truncates at 1,000 keys

## 2. Basic Object Operations

Each object call addresses one key; there is no partial update or append.

- Frequent in-place small updates rewrite the whole object each time
- Store the S3 key in a database, not a presigned Uniform Resource Locator (URL)

### 2.1 Put With Metadata

A single PUT writes bytes, content type, and user metadata in one request.

- Use for small objects
  - Code comment guidance: below ~100 mebibytes (MiB)
  - Hard cap: 5 gibibytes (GiB) per single PUT
- The code also passes Server-Side Encryption with Key Management Service keys (SSE-KMS) per request
  - See [06 Encryption](03s3.06encryption.md)

**Java**

```java
// infra/_03db_03s3/S3LakeStore.java
@Override
public ObjectInfo put(String key, byte[] body, String contentType, Map<String, String> metadata) {
    PutObjectResponse r = s3.putObject(PutObjectRequest.builder()
                    .bucket(bucket).key(key).contentType(contentType).metadata(metadata)
                    .serverSideEncryption(ServerSideEncryption.AWS_KMS)
                    .ssekmsKeyId(kmsKeyAlias)
                    .bucketKeyEnabled(true)
                    .build(),
            RequestBody.fromBytes(body));
    return new ObjectInfo(key, body.length, r.eTag(), r.versionId(), contentType,
            r.serverSideEncryptionAsString(), r.ssekmsKeyId(), metadata);
}
```

**Python**

```python
# app/infra/_03db_03s3.py
def put(key: str, body: bytes, content_type: str, metadata: dict[str, str]) -> ObjectInfo:
    r = _s3().put_object(
        Bucket=_bucket(), Key=key, Body=body, ContentType=content_type, Metadata=metadata, **_kms_args()
    )
    return ObjectInfo(
        key, len(body), r.get("ETag"), r.get("VersionId"), content_type,
        r.get("ServerSideEncryption"), r.get("SSEKMSKeyId"), metadata,
    )
```

**Catch**

- User metadata is immutable after write
  - Changing it = copy the object onto itself
- SSE-KMS needs `kms:GenerateDataKey` on the caller

### 2.2 Get and Head

GET returns the body; HEAD returns size, Entity Tag (ETag), metadata, and encryption without the body.

- GET of the whole body into memory: only for small objects
  - Stream (`ResponseInputStream` / `Body`) otherwise
- HEAD is the cheap existence and size check

**Java**

```java
// infra/_03db_03s3/S3LakeStore.java
@Override
public byte[] get(String key) {
    ResponseBytes<GetObjectResponse> bytes = s3.getObject(
            GetObjectRequest.builder().bucket(bucket).key(key).build(), ResponseTransformer.toBytes());
    return bytes.asByteArray();
}

@Override
public ObjectInfo head(String key) {
    HeadObjectResponse h = s3.headObject(HeadObjectRequest.builder().bucket(bucket).key(key).build());
    return new ObjectInfo(key, h.contentLength(), h.eTag(), h.versionId(), h.contentType(),
            h.serverSideEncryptionAsString(), h.ssekmsKeyId(), h.metadata());
}
```

**Python**

```python
# app/infra/_03db_03s3.py
def get(key: str) -> bytes:
    return _s3().get_object(Bucket=_bucket(), Key=key)["Body"].read()


def head(key: str) -> ObjectInfo:
    r = _s3().head_object(Bucket=_bucket(), Key=key)
    return ObjectInfo(
        key, r["ContentLength"], r.get("ETag"), r.get("VersionId"), r.get("ContentType"),
        r.get("ServerSideEncryption"), r.get("SSEKMSKeyId"), r.get("Metadata", {}),
    )
```

**Catch**

- Missing key on GET = `NoSuchKey` (404)
  - With versioning, a delete marker on top also reads as 404
- HEAD has no error body
  - A missing key is a bare 404 (Python: code `"404"`)
  - 403 instead of 404 if `s3:ListBucket` is missing

### 2.3 Delete

DELETE never fails for a missing key; on a versioned bucket it only adds a marker.

- Versioned bucket ⇒ delete writes a delete marker
  - Data stays and is recoverable
- Only a delete with a `versionId` removes bytes permanently

**Java**

```java
// infra/_03db_03s3/S3LakeStore.java
@Override
public void delete(String key) {
    s3.deleteObject(DeleteObjectRequest.builder().bucket(bucket).key(key).build());
}
```

**Python**

```python
# app/infra/_03db_03s3.py
def delete(key: str) -> None:
    _s3().delete_object(Bucket=_bucket(), Key=key)
```

**Catch**

- Surprise 404 after delete is a delete marker
  - See [07 Versioning](03s3.07versioning-lifecycle.md)
