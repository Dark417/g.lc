## 1. Versioning

With versioning, overwrites and deletes never destroy old bytes.

- Overwrite creates a new version
- DELETE adds a delete marker; old bytes stay
- Versioning can be suspended, never turned off
- Permissions
  - Reading a specific version needs `s3:GetObjectVersion`
  - Listing needs `s3:ListBucketVersions`

→ A delete marker is the latest version  
⇒ GET returns a surprise 404  
→ `ListObjectVersions` shows the marker  
→ Delete the marker to restore the previous version

### 1.1 List Versions

**Java**

```java
// infra/_03db_03s3/S3LakeStore.java
@Override
public List<ObjectVersion> listVersions(String keyPrefix) {
    List<ObjectVersion> out = new ArrayList<>();
    s3.listObjectVersionsPaginator(ListObjectVersionsRequest.builder().bucket(bucket).prefix(keyPrefix).build())
            .forEach(page -> {
                page.versions().forEach(v -> out.add(new ObjectVersion(
                        v.key(), v.versionId(), Boolean.TRUE.equals(v.isLatest()), false, v.lastModified(), v.size())));
                // delete markers come in a separate list; size 0
                page.deleteMarkers().forEach(m -> out.add(new ObjectVersion(
                        m.key(), m.versionId(), Boolean.TRUE.equals(m.isLatest()), true, m.lastModified(), 0L)));
            });
    return out;
}
```

**Python**

```python
# app/infra/_03db_03s3.py
def list_versions(key_prefix: str) -> list[ObjectVersion]:
    out: list[ObjectVersion] = []
    for page in _s3().get_paginator("list_object_versions").paginate(Bucket=_bucket(), Prefix=key_prefix):
        for v in page.get("Versions", []):
            out.append(ObjectVersion(v["Key"], v["VersionId"], v["IsLatest"], False, v["LastModified"], v["Size"]))
        for m in page.get("DeleteMarkers", []):
            out.append(ObjectVersion(m["Key"], m["VersionId"], m["IsLatest"], True, m["LastModified"], 0))
    return out
```

**Catch**

- Lifecycle noncurrent expiry (30 days under `raw/`) removes old versions from this list

### 1.2 Read a Specific Version

Use for rollback or audit.

**Java**

```java
// infra/_03db_03s3/S3LakeStore.java
@Override
public byte[] getVersion(String key, String versionId) {
    return s3.getObject(GetObjectRequest.builder().bucket(bucket).key(key).versionId(versionId).build(),
            ResponseTransformer.toBytes()).asByteArray();
}
```

**Python**

```python
# app/infra/_03db_03s3.py
def get_version(key: str, version_id: str) -> bytes:
    return _s3().get_object(Bucket=_bucket(), Key=key, VersionId=version_id)["Body"].read()
```

**Catch**

- Passing a delete marker's versionId returns 405, not 404

## 2. Lifecycle

Lifecycle rules transition or expire current and noncurrent versions separately.

- Terraform rules (no app code; see [`modules/03db_03s3/main.tf`](../../terraform/modules/03db_03s3/main.tf))
  - `raw/` → STANDARD_IA at 30 days → GLACIER_IR at 180 days
  - Noncurrent versions expire at 30 days
  - Abort incomplete multipart uploads after 7 days
- Rules run asynchronously (about daily)
  - Not exact to the hour; do not rely on exact timing
- Minimum storage duration charges apply
  - Infrequent Access (IA): 30 days
  - Glacier classes: see table below
- Without noncurrent expiry, cost grows forever
- Expired-object-delete-marker cleanup is needed to remove orphan markers

```hcl
# illustrative: shape of the rules in the Terraform module
rule {
  id     = "raw-tiering"
  filter { prefix = "raw/" }
  transition { days = 30  storage_class = "STANDARD_IA" }
  transition { days = 180 storage_class = "GLACIER_IR" }
  noncurrent_version_expiration { noncurrent_days = 30 }
  abort_incomplete_multipart_upload { days_after_initiation = 7 }
}
```

**Catch**

→ Versions + IA minimum charges + small objects in IA  
⇒ Cost growth  
→ Detect with Cost Explorer, Storage Lens  
→ Noncurrent expiry, compact small files, right class

## 3. Storage Classes

Pick the class by read frequency and how fast a read must return.

| Class | Use | Retrieval | Catch |
|---|---|---|---|
| STANDARD | hot data | milliseconds (ms), no fee | highest per-gigabyte (GB) price |
| INTELLIGENT_TIERING | unknown access | ms for frequent/infrequent tiers | monitoring fee per object |
| STANDARD_IA | rare reads, needs ms | ms, per-GB fee | 30-day minimum, 128 kilobytes (KB) billing floor |
| GLACIER_IR | archive, rare ms reads | ms, higher per-GB fee | 90-day minimum |
| GLACIER_FLEXIBLE / DEEP_ARCHIVE | cold archive | minutes to hours | restore request needed; 90 / 180-day minimum |

- Prices change; check the S3 pricing page (not quoted here)
- No code: transitions are declared in Terraform
