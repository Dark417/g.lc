## 1. Multipart Upload

Multipart splits one object into independently retried parts and commits them in one step.

### 1.1 Mechanism

The object stays invisible until Complete.

→ `CreateMultipartUpload` returns an uploadId  
→ `UploadPart` (part number 1..10,000, parallel, each retried on its own)  
→ `CompleteMultipartUpload` with the list of part numbers + Entity Tags (ETags)  
⇒ The object appears atomically only after Complete

- Per-part retry is idempotent by part number
  - Same part number overwrites the earlier attempt
- Complete is the atomic commit

### 1.2 Limits

Part and object sizes are fixed by Simple Storage Service (S3; S3 docs, "Amazon S3 multipart upload limits").

- Part size 5 mebibytes (MiB) to 5 gibibytes (GiB)
  - Only the last part may be below 5 MiB
- Max 10,000 parts
- Max object 5 tebibytes (TiB)
- Single PUT is capped at 5 GiB
- Part size floor = object size / 10,000
  - 50 gigabytes (GB) at 5 MiB parts needs ~10,240 parts ⇒ exceeds the limit
  - So use >= 8 MiB parts for 50 GB
- Parallelism is bounded by Network Interface Card (NIC) and memory (threads × part size)

### 1.3 Low-Level Code

The code shows create → part loop → complete, with abort on any failure.

**Java**

```java
// infra/_03db_03s3/S3LakeStore.java
static final int MIN_PART_BYTES = 5 * 1024 * 1024; // every part but the last >= 5 MiB

@Override
public ObjectInfo multipartUpload(String key, Path file, int partSizeBytes) {
    if (partSizeBytes < MIN_PART_BYTES) {
        throw new IllegalArgumentException("part size must be >= 5 MiB (only the last part may be smaller)");
    }
    String uploadId = s3.createMultipartUpload(CreateMultipartUploadRequest.builder()
            .bucket(bucket).key(key)
            .serverSideEncryption(ServerSideEncryption.AWS_KMS).ssekmsKeyId(kmsKeyAlias)
            .build()).uploadId();
    try (InputStream in = Files.newInputStream(file)) {
        // ... size, parts list, partNumber = 1 (1..10,000)
        while (sent < size) {
            byte[] buf = in.readNBytes(partSizeBytes);
            // Retrying one failed part is safe: same partNumber overwrites the earlier attempt.
            String etag = s3.uploadPart(UploadPartRequest.builder()
                            .bucket(bucket).key(key).uploadId(uploadId).partNumber(partNumber).build(),
                    RequestBody.fromBytes(buf)).eTag();
            parts.add(CompletedPart.builder().partNumber(partNumber).eTag(etag).build());
            // ... sent += buf.length; partNumber++
        }
        s3.completeMultipartUpload(CompleteMultipartUploadRequest.builder()
                .bucket(bucket).key(key).uploadId(uploadId)
                .multipartUpload(CompletedMultipartUpload.builder().parts(parts).build()).build());
        return head(key);
    } catch (IOException | RuntimeException e) {
        // Partial failure: free the stored parts, otherwise they are billed invisibly.
        s3.abortMultipartUpload(AbortMultipartUploadRequest.builder()
                .bucket(bucket).key(key).uploadId(uploadId).build());
        throw e instanceof RuntimeException re ? re : new IllegalStateException("multipart failed", e);
    }
}
```

**Python**

```python
# app/infra/_03db_03s3.py
def multipart_upload(key: str, file: Path, part_size: int = MIN_PART_BYTES) -> ObjectInfo:
    if part_size < MIN_PART_BYTES:
        raise ValueError("part size must be >= 5 MiB (only the last part may be smaller)")
    s3 = _s3()
    upload_id = s3.create_multipart_upload(Bucket=_bucket(), Key=key, **_kms_args())["UploadId"]
    try:
        parts: list[dict[str, Any]] = []
        with file.open("rb") as fh:
            part_number = 1  # 1..10,000
            while chunk := fh.read(part_size):
                etag = s3.upload_part(
                    Bucket=_bucket(), Key=key, UploadId=upload_id, PartNumber=part_number, Body=chunk
                )["ETag"]
                parts.append({"PartNumber": part_number, "ETag": etag})
                part_number += 1
        s3.complete_multipart_upload(
            Bucket=_bucket(), Key=key, UploadId=upload_id, MultipartUpload={"Parts": parts}
        )
    except Exception:
        s3.abort_multipart_upload(Bucket=_bucket(), Key=key, UploadId=upload_id)  # free billed parts
        raise
    return head(key)
```

**Catch**

→ Process crashes between create and complete  
⇒ Stored parts stay and bill invisibly  
→ Abort in `except` / `catch`  
→ Lifecycle `AbortIncompleteMultipartUpload` (Terraform: 7 days)  
→ Detect leftovers with `ListMultipartUploads`

- The multipart ETag is not a Message-Digest Algorithm 5 (MD5) of the content

## 2. Managed Transfers

Transfer Manager / `upload_file` picks part size, parallelizes, and aborts on failure; use it as the default for files.

### 2.1 Client Beans

Java needs an async client with multipart enabled under the Transfer Manager.

- Every client reuses the shared Region + credentials provider (one credential cache)
- Creating beans makes no network call
- Python uses `app.shared.aws.client("s3")`

**Java**

```java
// config/_03db_03s3/S3Config.java
// Sync client: default for request/response calls. SDK retries (standard mode) built in.
@Bean(destroyMethod = "close")
public S3Client s3Client(Region region, AwsCredentialsProvider credentials) {
    return S3Client.builder().region(region).credentialsProvider(credentials).build();
}

// multipartEnabled(true): async client splits large put/get into parts (Java-based, no CRT).
@Bean(destroyMethod = "close")
public S3AsyncClient s3AsyncClient(Region region, AwsCredentialsProvider credentials) {
    return S3AsyncClient.builder().region(region).credentialsProvider(credentials)
            .multipartEnabled(true).build();
}

// Transfer Manager = file/dir upload+download with parallel parts and progress.
@Bean(destroyMethod = "close")
public S3TransferManager s3TransferManager(S3AsyncClient asyncClient) {
    return S3TransferManager.builder().s3Client(asyncClient).build();
}
```

**Catch**

- Without `multipartEnabled(true)`, a big async `putObject` is ONE request (5 GiB cap)

### 2.2 Transfer Upload and Download

Downloads use parallel ranged GETs; uploads use parallel parts.

**Java**

```java
// infra/_03db_03s3/S3LakeStore.java
@Override
public ObjectInfo transferUpload(String key, Path file) {
    CompletedFileUpload done = transfer.uploadFile(UploadFileRequest.builder()
            .source(file)
            .putObjectRequest(PutObjectRequest.builder().bucket(bucket).key(key)
                    .serverSideEncryption(ServerSideEncryption.AWS_KMS).ssekmsKeyId(kmsKeyAlias).build())
            .build()).completionFuture().join();
    // ... map done.response() to ObjectInfo
}

@Override
public long transferDownload(String key, Path target) {
    CompletedFileDownload done = transfer.downloadFile(DownloadFileRequest.builder()
            .getObjectRequest(GetObjectRequest.builder().bucket(bucket).key(key).build())
            .destination(target).build()).completionFuture().join();
    return done.response().contentLength();
}
```

**Python**

```python
# app/infra/_03db_03s3.py
def transfer_upload(key: str, file: Path) -> None:
    config = TransferConfig(
        multipart_threshold=16 * 1024 * 1024,  # multipart above 16 MiB
        multipart_chunksize=16 * 1024 * 1024,
        max_concurrency=8,  # x chunk size = memory bound
        use_threads=True,
    )
    _s3().upload_file(str(file), _bucket(), key, ExtraArgs=_kms_args(), Config=config)


def transfer_download(key: str, target: Path) -> None:
    _s3().download_file(_bucket(), key, str(target), Config=TransferConfig(max_concurrency=8))
```

**Catch**

- Throughput is bounded by local disk / NIC
- Python uses threads ⇒ `max_concurrency` × part size bounds memory use
- Java download: the target file must not exist yet (fails rather than overwrite)
- Python download writes a temp file, then renames
  - A failure leaves no partial target
