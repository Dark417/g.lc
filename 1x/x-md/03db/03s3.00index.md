## 1. One-Minute Version

S3 is a regional key → bytes store; most of its traps come from treating it as a file system.

- What
  - S3 = regional object store, a flat key → bytes namespace, addressed over Hypertext Transfer Protocol Secure (HTTPS)
  - Object = key + bytes + metadata + optional version id
- Why
  - Cheap, durable bytes without servers, disks, or capacity planning
  - Data lake, backups, user uploads, static assets
- How
  - No real folders
    - A "folder" is a key prefix
    - A delimiter groups keys at list time
  - Reads see the latest write: strong read-after-write consistency since Dec 2020
  - Large files go as multipart
    - 5 mebibytes (MiB) minimum part except the last
    - Max 10,000 parts, 5 tebibytes (TiB) object
  - Browsers upload directly through presigned Uniform Resource Locators (URLs), signed by our credentials
  - Server-Side Encryption with Key Management Service keys (SSE-KMS) encrypts per object
    - S3 Bucket Keys cut the Key Management Service (KMS) request count
  - Versioning keeps old bytes
    - Lifecycle moves or expires them
  - Create-only writes use `If-None-Match: *` (since Aug 2024)
- Catch
  - Not a file system
    - No rename, no append, no partial update
    - No atomic multi-object change
  - Request rate is per prefix, not per bucket
    - 3,500 writes / 5,500 reads per second
  - Versioning + abandoned multipart uploads silently grow the bill
- 🗣 "S3 is a giant key-value store for blobs; folders are a listing trick, and strong consistency means a successful PUT is immediately readable."
- 🗣 "I put bytes in S3 and a pointer in a database; I never put blobs in the database."

## 2. Architecture Picture

The lake bucket receives bytes from browsers and the app, and asks KMS for keys once per bucket period.

```text
 client ──presigned PUT──────────────┐
   │                                 ▼
 app ──PutObject / multipart──▶  bucket x-lake-<acct>
   │                              ├─ raw/dt=2026-01-01/part-0.json   (lifecycle → IA → GLACIER_IR)
   │                              ├─ curated/...
   │                              └─ versions + delete markers
   └─ SSE-KMS ──▶ KMS (alias/x-data); Bucket Key = 1 KMS call per bucket-period
```

Notice that bytes never pass through the app on the presigned path, and KMS is not called per object once Bucket Keys are on.
