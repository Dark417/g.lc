# 03db.03s3.06encryption Encryption

> Server-Side Encryption with Simple Storage Service managed keys (SSE-S3) vs Server-Side Encryption with Key Management Service keys (SSE-KMS), and how Simple Storage Service (S3) Bucket Keys keep Key Management Service (KMS) cost and throttling under control.

## 1. SSE-S3

S3 manages the keys; you get encryption at rest with no control.

- Free
- Default for all new objects since Jan 2023
- No key policy, no per-key audit, no revoke

## 2. SSE-KMS

Each object gets a data key wrapped by a KMS key you control.

- Per-object data key wrapped by a KMS key
- Gives
  - Key policy
  - Audit in CloudTrail
  - Per-key disable (revoke)
- Cost
  - Every PUT / GET without Bucket Keys calls KMS
  - Request charge + KMS Application Programming Interface (API) rate quota

## 3. S3 Bucket Keys

S3 gets one bucket-level key from KMS and derives object data keys locally.

→ S3 asks KMS for a bucket-level key  
→ S3 derives each object data key locally  
⇒ About 1 KMS call per bucket-period instead of per object

- Cuts KMS requests by up to 99% (Amazon Web Services (AWS)-stated)
- Terraform enables `bucket_key_enabled`
- Limits
  - Not applied to objects already written without it
  - Changes CloudTrail granularity

## 4. Code

Bucket default is already SSE-KMS; the code still passes the key alias per request to show the override.

**Java**

```java
// infra/_03db_03s3/S3LakeStore.java
// x.s3.kms-key-alias defaults to alias/x-data
PutObjectResponse r = s3.putObject(PutObjectRequest.builder()
                .bucket(bucket).key(key).contentType(contentType).metadata(metadata)
                .serverSideEncryption(ServerSideEncryption.AWS_KMS)
                .ssekmsKeyId(kmsKeyAlias)
                .bucketKeyEnabled(true) // fewer KMS calls per object -> lower KMS request cost
                .build(),
        RequestBody.fromBytes(body));
```

**Python**

```python
# app/infra/_03db_03s3.py
def _kms_args() -> dict[str, Any]:
    # SSE-KMS per request (bucket default is already SSE-KMS); Bucket Keys cut KMS request cost.
    return {
        "ServerSideEncryption": "aws:kms",
        "SSEKMSKeyId": get_settings().s3_kms_key_alias,
        "BucketKeyEnabled": True,
    }
```

**Catch**

→ Caller lacks `kms:GenerateDataKey` (write) or `kms:Decrypt` (read)  
⇒ 403 AccessDenied whose error names KMS  
→ Grant KMS use in both Identity and Access Management (IAM) and the key policy

## 5. Access and Revocation

KMS adds a second permission gate on top of S3.

- Cross-account readers need both
  - Bucket policy access
  - KMS key policy access
- Disabling the KMS key makes all objects under it unreadable
- Best practice: default encryption SSE-KMS + Bucket Key
  - KMS audit without per-request KMS cost explosion
