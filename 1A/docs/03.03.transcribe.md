## 0. One-minute version
- What
  - Managed speech-to-text: audio in, JSON transcript out
  - Batch (file in S3) and streaming (WebSocket / HTTP2, live audio)
- Why
  - Audio is the biggest unstructured source nobody can search or summarize
  - A transcript turns calls and meetings into text an LLM can use
- How
  - `StartTranscriptionJob` with an S3 media URI, a language (or language ID), and Settings
  - Poll `GetTranscriptionJob` until COMPLETED; the transcript JSON lands in S3
  - Add: custom vocabulary (domain terms), vocabulary filter (mask / remove / tag words), speaker diarization, channel identification, PII redaction
  - Then summarize with Bedrock `converse`
- Catch
  - Job names are unique per account and Region ⇒ idempotent naming needed
  - Speaker labels and channel identification are mutually exclusive
  - Language support differs per feature (redaction, diarization, streaming): check the supported-languages page
  - Redaction only changes the text; audio is untouched
- 🗣 "Transcribe is the ear of a GenAI pipeline: audio to JSON, then an LLM does the thinking."
- 🗣 "Name jobs deterministically so a retry does not create a second job."
- 🗣 "Redact before the transcript reaches the model or the log."

## 1. Concept

### 1.1 Why it was created
- The pain: ASR needed ML teams, GPUs and per-language models
- Transcribe = ASR as an API with domain adaptation knobs
- Use cases
  - Contact-center analytics, meeting notes, media captions
  - Voice input to an agent
  - Compliance search over recordings

### 1.2 Picture

```
 S3 transcribe/in/call.wav
        │ StartTranscriptionJob(name, Settings, ContentRedaction, OutputBucketName, OutputKey)
        ▼
   Transcribe (QUEUED → IN_PROGRESS → COMPLETED | FAILED)
        ▼
 S3 transcribe/out/<name>.json  ──► parse turns ──► Bedrock converse ──► summary
```

### 1.3 Batch vs streaming
- Batch
  - Whole file, higher accuracy options, all features
  - Async: minutes, not real-time
- Streaming
  - Partial results while audio arrives; seconds of latency
  - Fewer features/languages; SDK for streaming not shown in code here
- Pick by latency need, not by habit

### 1.4 Accuracy knobs
- Custom vocabulary
  - A list of phrases (product names, jargon); words with hyphens for multi-word terms
  - Cheap, instant; no training
  - Larger accuracy lift: custom language models (CLM), not coded
- Vocabulary filter
  - Words to `mask` (`***`), `remove`, or `tag` (flag, keep text)
  - Filters text output only
- Language identification
  - `IdentifyLanguage` with optional `LanguageOptions` to narrow the candidates; exclusive with `LanguageCode`

### 1.5 Who spoke
- Speaker diarization: `ShowSpeakerLabels` + `MaxSpeakerLabels` (2–30); one mixed audio channel
- Channel identification: `ChannelIdentification` for stereo (agent left, customer right); more reliable than diarization
- Exclusive: choose one

### 1.6 PII redaction
- `ContentRedaction`: `RedactionType=PII`, `RedactionOutput = redacted | redacted_and_unredacted`, optional `PiiEntityTypes` (default ALL)
- `redacted_and_unredacted` writes both transcripts: store the raw one encrypted with a tighter policy
- Detail and comparison with Comprehend and Guardrails: [04.02](04.02.pii-redaction.md)

### 1.7 Call Analytics (brief)
- Separate API (`StartCallAnalyticsJob`): sentiment per turn, talk-time, interruptions, categories, issue summary
- Use when the whole job is contact-center; otherwise plain transcription plus an LLM is simpler

### 1.8 Output JSON shape
- `results.transcripts[0].transcript`: full text
- `results.items[]`: word or punctuation, with `start_time`, `end_time`, `alternatives[{content, confidence}]`, `speaker_label` when diarized
- `results.speaker_labels.segments[]`: speaker turns with `start_time`, `end_time`, items
- `results.channel_labels.channels[]` for channel identification
- Timestamps are strings in seconds

### 1.9 As a GenAI input
→ Transcribe (redacted) → chunk by speaker turn or time window  
→ summarize / extract action items with an LLM  
→ index chunks (with timestamp metadata) for RAG  
⇒ Long calls exceed context: summarize per window, then reduce.

## 2. When to use / not
- Use
  - Audio you must search, summarize or analyze, on AWS, with PII controls
- Don't use
  - Need custom model weights or unusual languages ⇒ Whisper on SageMaker
  - Real-time voice conversation ⇒ speech-to-speech (Nova Sonic) or streaming

## 3. Knobs and best practices
- Deterministic job name = hash of media URI + settings ⇒ retries are idempotent
- Write output to your bucket + prefix with `OutputBucketName` and `OutputKey` and a CMK ⇒ otherwise Transcribe uses a service-owned location with a temporary URL
- Poll with backoff (jobs take minutes), or use EventBridge on job state change
- Vocabulary first (hours of work saved), CLM only when measured WER stays high
- Stereo calls ⇒ channel identification, not diarization
- Redact before logging; keep unredacted output access-controlled
- Keep job lifecycle: delete old jobs (retention in the console list is limited) and lifecycle the S3 prefix

## 4. Comparison

| Option | What it is | Strength | Weakness | Choose when |
|---|---|---|---|---|
| Amazon Transcribe | Managed ASR | No ops; redaction, diarization, vocab | Language/feature gaps; per-minute price | AWS pipeline, PII needs |
| Whisper on SageMaker | Open model on your endpoint | Many languages; full control | You run GPUs, scaling, redaction | Unsupported languages, offline |
| Google/Azure speech | Other clouds | Strong models | Cross-cloud data movement | Already on that cloud |
| Prompt a multimodal model with audio | LLM reads audio directly | One call for transcript + task | Less control, cost, length limits | Short clips, prototypes |

- Default: Transcribe for AWS workloads, unless the language is unsupported (Whisper) or you need model control
- Deciding variable: language coverage and who runs the infrastructure

## 5. Failure modes

| Failure | Trigger | Detect | Fix |
|---|---|---|---|
| `ConflictException` | Job name reused | API error | Deterministic name + get the existing job |
| Job FAILED | Bad format, wrong sample rate | `FailureReason` | Convert audio, set `MediaFormat` |
| `BadRequest` on settings | Diarization + channel ID together | API error | Pick one |
| Output unreadable | S3/KMS permission for the caller | AccessDenied | Allow `s3:PutObject`, KMS data key |
| Vocabulary not ready | State PENDING/FAILED | `GetVocabulary` | Wait for READY; fix phrase format |
| PII leaks into the summary | Raw transcript sent to the LLM | Review | Redact first, summarize redacted |
| Cost surprise | Re-transcribing duplicates | Billing | Idempotent names, dedup by hash |

## 6. Interview questions

**Q1:** Batch vs streaming transcription?

**L4 answer**
- Batch: file in S3, async, most features
- Streaming: live audio, partial results, fewer features

**L5 extra**
- Streaming trades accuracy and features for latency
- Choose by user-visible latency requirement

**Q2:** How do you improve accuracy for domain terms?

**L4 answer**
- Custom vocabulary; custom language model if needed

**L5 extra**
- Measure WER before and after on a golden set
- Vocabulary is cheap and reversible; CLM needs training data

**Q3:** Diarization vs channel identification?

**L4 answer**
- Diarization separates speakers in one channel; channel ID uses stereo channels

**L5 extra**
- Channel ID is deterministic; diarization is a model and degrades with overlapping speech
- They are mutually exclusive

**Q4:** How does PII redaction work and what does it cost you?

**L4 answer**
- `ContentRedaction` with types; redacted transcript; optionally the original too

**L5 extra**
- Text-only: audio keeps the PII ⇒ lifecycle the audio too
- Dual output doubles the sensitive store

**Q5:** How do you feed a transcript to an LLM?

**L4 answer**
- Parse turns, redact, summarize with `converse`

**L5 extra**
- Window long calls and reduce; keep timestamps as citation metadata

**L5-only Q6:** Design call-recording analytics for 100k calls a day.

**L5 answer**
- S3 event → queue → worker submits jobs with deterministic names
- EventBridge on completion → parse → LLM summary → store
- Throttle to quota; DLQ failed jobs; per-call cost metric
- Redact before analytics; raw audio and transcript in a restricted bucket with lifecycle

**L5-only Q7:** When would you pick Whisper over Transcribe?

**L5 answer**
- Unsupported language or domain needing fine-tuned weights
- Volume high enough that GPU hours beat per-minute pricing
- You then own redaction, diarization (extra models), scaling and monitoring
