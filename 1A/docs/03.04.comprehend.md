## 0. One-minute version
- What
  - Managed NLP: entities, key phrases, sentiment, language, syntax, classification
  - Comprehend Medical: clinical entities, ICD-10-CM / RxNorm / SNOMED linking, PHI
- Why
  - Cheap, fast, deterministic signals about text
  - Use them to enrich, filter or route before an expensive LLM call
- How
  - Sync `Detect*` for one text; `BatchDetect*` for up to 25 documents per call (check the quota page)
  - Async `Start*DetectionJob` for large S3 corpora
  - Custom classifier / entity recognizer: you train, then call through an endpoint
- Catch
  - Per-unit pricing (100 characters per unit, minimum charge per request; check the pricing page)
  - Custom models cost training + hourly endpoint (idle endpoints bill)
  - Sync text size limits ⇒ chunk long text
  - Batch calls return partial failures in `ErrorList`
  - Language support varies per API
- 🗣 "Comprehend answers narrow NLP questions at fixed cost and latency; the LLM does the rest."
- 🗣 "Detect, then decide: sentiment and key phrases choose the prompt and the model tier."
- 🗣 "Batch APIs fail per item: always read `ErrorList`."

## 1. Concept

### 1.1 Why it was created
- The pain: NLP needed trained models per task and per language
- Comprehend packages the common tasks as API calls
- Use cases
  - Voice-of-customer sentiment, topic extraction
  - Language detection to route to a translation or the right index
  - Medical text → coded entities

### 1.2 APIs

| API | Returns | Notes |
|---|---|---|
| `DetectEntities` | PERSON, ORGANIZATION, LOCATION, DATE, QUANTITY, ... with score and offsets | Custom entity recognizer via `EndpointArn` |
| `DetectKeyPhrases` | Noun phrases with score | Good for tagging, search facets |
| `DetectSentiment` | POSITIVE / NEGATIVE / NEUTRAL / MIXED + scores | Whole text |
| `DetectTargetedSentiment` | Sentiment per entity mention | Where the opinion lands |
| `DetectDominantLanguage` | Language codes + scores | No language input needed |
| `DetectSyntax` | Tokens with part-of-speech | Rarely needed with LLMs |
| `ClassifyDocument` | Class labels | Needs a custom classifier endpoint (or a flywheel) |
| `DetectPiiEntities` | PII spans | See 04.02 |

- `BatchDetect*`: list of texts in, `ResultList` (with `Index`) + `ErrorList` (`Index`, `ErrorCode`, `ErrorMessage`) out
- Async jobs: `StartEntitiesDetectionJob` etc. read S3, write S3; poll `Describe*Job`

### 1.3 Custom models
- Custom classification: labeled CSV in S3 → `CreateDocumentClassifier` → model → real-time endpoint or async batch
- Custom entity recognition: annotations or entity list → `CreateEntityRecognizer`
- Costs: training time + model management + endpoint per inferencing-unit-hour (check the pricing page)
- Terraform has `aws_comprehend_document_classifier`; a commented example is in the `.tf`, not declared (cost)
- Alternative today: few-shot an LLM classifier; custom models win at high volume and stable labels

### 1.4 Comprehend Medical
- Separate service (`comprehendmedical`)
- `DetectEntitiesV2`: medications, conditions, tests, anatomy, with traits (negation, ...)
- `DetectPHI`: protected health information entities
- `InferICD10CM`, `InferRxNorm`, `InferSNOMEDCT`: link text to codes with scores
- Limits: text size per call is small (documented in characters; check the quota page)
- HIPAA-eligible; still your data governance applies

### 1.5 Pattern: Comprehend + Lambda + Bedrock (lecture 51)

```
 request ─► Lambda ─► Comprehend (language, sentiment, key phrases)
                         │ decision
              ┌──────────┴───────────┐
              ▼                      ▼
   fast model + short prompt   strong model + empathetic prompt
              └──────────┬───────────┘
                         ▼ converse → answer
```

→ Detect language and sentiment (cheap, deterministic)  
→ Pick prompt template and model tier from the result  
→ Add key phrases to the prompt or to the retrieval query  
⇒ LLM spend goes where it matters; behavior is explainable

## 2. When to use / not
- Use
  - High-volume, narrow tasks with fixed labels
  - You need deterministic output, tight latency, predictable cost
  - Pre-filter before an LLM
- Don't use
  - Open-ended understanding, new labels each week ⇒ LLM
  - Sarcasm, domain slang, long-context reasoning ⇒ LLM
  - Training endpoints for low volume ⇒ idle cost

## 3. Knobs and best practices
- Pass `LanguageCode` when known; otherwise detect first (one cheap call)
- Batch up to 25 per call; split larger lists; read `ErrorList`, retry only failed indexes
- Cut text to the limit on sentence boundaries; sentiment of a truncated text is partial
- Cache results by text hash for repeated inputs
- Threshold on `Score` (for entities, ~0.8 is a common start; tune on your data)
- Delete custom endpoints when idle; use async batch for offline classification
- Don't log raw text (sensitive); the SDK marks inputs as sensitive

## 4. Comparison

| Option | What it is | Strength | Weakness | Choose when |
|---|---|---|---|---|
| Comprehend | Task-specific NLP APIs | Cheap, fast, deterministic, no prompts | Fixed tasks; custom models cost | High volume, fixed labels, pre-filter |
| Prompt an LLM | General model with instructions | Any task, any label, nuance | Per-token cost, latency, non-determinism | Low volume, open-ended, rapid change |
| Comprehend then LLM | Detect, route, then generate | Cost control + explainable routing | Two systems to run | Mixed traffic where cheap signal decides spend |
| Hugging Face on SageMaker | Open model endpoints | Control, fine-tuning | You operate it | Special languages/domains at scale |

- Default: LLM for flexibility at low volume; Comprehend when volume, latency or determinism dominates; Comprehend as router in front of the LLM when traffic is mixed
- Deciding variable: volume × label stability

## 5. Failure modes

| Failure | Trigger | Detect | Fix |
|---|---|---|---|
| `TextSizeLimitExceededException` | Text over the sync limit | API error | Chunk text |
| Silent partial batch failure | Reading only `ResultList` | Missing indexes | Check `ErrorList`, retry those |
| `UnsupportedLanguageException` | Language not supported for the API | API error | Detect language first; fall back to the LLM |
| Throttling | Burst of calls | `ThrottlingException` | Adaptive retries (shared client), backoff, batch |
| Idle cost | Custom endpoint left running | Cost report | Delete endpoint; use async jobs |
| Wrong routing | Sentiment of a truncated message | Review samples | Use full text; thresholds on score |
| PHI in logs | Raw clinical text logged | Log review | Never log inputs |

## 6. Interview questions

**Q1:** When Comprehend and when an LLM?

**L4 answer**
- Comprehend for fixed, high-volume tasks that need determinism and low cost
- LLM for open-ended or changing tasks

**L5 extra**
- Compare cost per 1k docs and p99 latency on your data
- Accuracy on domain language decides; benchmark both on a golden set

**Q2:** How do you process 1M documents?

**L4 answer**
- Async jobs reading S3, or batches of 25 in parallel with retries

**L5 extra**
- Jobs for offline; batch APIs for near-real-time
- Track failed indexes, throttling and cost per document

**Q3:** What is `ErrorList`?

**L4 answer**
- Per-item failures in batch calls with the item `Index`

**L5 extra**
- The HTTP call succeeds while items fail ⇒ idempotent per-item retry

**Q4:** Explain the Comprehend + Lambda + Bedrock pattern.

**L4 answer**
- Analyze text first, route on the result to a prompt and a model

**L5 extra**
- Saves cost by sending easy cases to a small model
- Risk: misrouting; sample and measure

**Q5:** What does Comprehend Medical add?

**L4 answer**
- Clinical entities, code linking (ICD-10-CM etc.), and PHI detection

**L5 extra**
- Scores per code; human review for coding decisions; HIPAA scope

**L5-only Q6:** Design triage of support tickets at 5M/day.

**L5 answer**
- Stream → Comprehend language + sentiment (batch) → rules route to LLM tiers
- Urgent negative → strong model + human queue; the rest → fast model or templates
- Metrics: routing mix, cost per ticket, escalation rate; shadow-evaluate routing weekly

**L5-only Q7:** Should you train a custom classifier?

**L5 answer**
- Only with stable labels, volume, and labeled data
- Endpoint hours vs per-token LLM cost at your volume
- Start with an LLM labeler to produce the training set, then distill
